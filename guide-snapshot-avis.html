Diagnostic — ce qui ne va pas aujourd'hui dans AvisController.java

🚨
Le snapshot est créé AVANT que l'avis ne soit sauvegardé, avec des valeurs complètement hardcodées ("test label str", "test Observation"). De plus, aucun WorkflowLog n'est créé. Résultat : les snapshots n'ont ni label ni commentaire réel, et l'historique de workflow est vide.
Java AvisController.java — ÉTAT ACTUEL (à corriger)
// ❌ PROBLÈME 1 : snapshot créé AVANT la sauvegarde de l'avis try { snapshotService.createSnapshot( avisDTO.getNumCaneva(), String.valueOf(avisDTO.getStructure()), "test label str", // ❌ HARDCODÉ String.valueOf(avisDTO.getMatricule()), String.valueOf(avisDTO.getMatricule()), "test Observation", // ❌ HARDCODÉ (devrait être avisDTO.getCommentaire()) avisDTO.getStatusAvis() ); } // ❌ PROBLÈME 2 : saveAvis() est appelé APRÈS le snapshot AvisDTO saved = avisService.saveAvis(avisDTO); // ❌ PROBLÈME 3 : aucun WorkflowLog n'est créé // ❌ PROBLÈME 4 : l'avisDTO n'a pas de champ structureLabel ni toStructureCode

🔴 Problème 1 — Ordre inversé

Le snapshot est pris avant que l'avis soit sauvegardé en base. Si saveAvis() échoue, le snapshot existe mais pointe sur une donnée non enregistrée.

Fix : Créer le snapshot après avisService.saveAvis(avisDTO).

🔴 Problème 2 — Valeurs hardcodées

structureLabel = "test label str" et observations = "test Observation" sont des valeurs de test jamais remplacées par les vraies données.

Fix : Passer avisDTO.getStructureLabel() et avisDTO.getCommentaire().

🟠 Problème 3 — Pas de WorkflowLog

Aucune entrée dans CanevasWorkflowLog n'est créée lors de l'envoi d'un avis. L'historique "History" est donc incomplet.

Fix : Appeler workflowLogService.log() après chaque snapshot réussi.

🟠 Problème 4 — AvisDTO incomplet

AvisDTO n'a pas de champ structureLabel ni toStructureCode. Le backend ne peut donc pas savoir vers quelle structure l'avis est transmis.

Fix : Ajouter 2 champs à AvisDTO.

Java AvisController.java — Étape 3c : ajouter ces 2 méthodes privées à la fin de la classe
/** * Mappe le statusAvis frontend vers le statut du canvas à enregistrer dans le snapshot. * Reflète exactement la logique de AvisService.saveAvis(). */ private String resolveStatusAtSnapshot(String statusAvis, String avisValue) { if (statusAvis == null) return "INCONNU"; return switch (statusAvis) { case "PEC_CCA" -> "PEC_DONNEE"; case "PRES_VALIDER" -> "VALID_DONNEE"; case "CORRIGER" -> "CORRIGE_DONNEE"; case "PEC_AVIS_DEC" -> "PEC_AVIS_DEC"; case "CORRIGER2" -> "CORRIGE_AVIS_DEC"; case "VALIDER" -> "VALIDER_DR"; case "Envoyer" -> "EN_COURS_ETUDE"; case "Décision Finale" -> ("1".equals(avisValue)) ? "DEC_FINAL_PRISE_ACCORD" : "DEC_FINAL_PRISE_REJET"; default -> statusAvis; }; } /** * Mappe le statusAvis frontend vers l'action à enregistrer dans CanevasWorkflowLog. */ private String resolveWorkflowAction(String statusAvis) { if (statusAvis == null) return "ACTION_INCONNUE"; return switch (statusAvis) { case "PEC_CCA" -> "PRENDRE_EN_CHARGE"; case "Envoyer" -> "ENVOYER"; case "PRES_VALIDER" -> "PRE_VALIDER"; case "CORRIGER" -> "REFOULER"; case "PEC_AVIS_DEC" -> "PRENDRE_EN_CHARGE"; case "VALIDER" -> "VALIDER"; case "CORRIGER2" -> "REFOULER"; case "Décision Finale" -> "DECISION_FINALE"; default -> statusAvis.toUpperCase(); }; }
