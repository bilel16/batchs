Snapshot History — Documentation Technique & Fonctionnelle

Guide complet pour comprendre, maintenir et améliorer le système d'historique de snapshots du projet Canevas Agricole. Destiné aux développeurs débutants.

Angular 16+ Signals Spring Boot Oracle / JPA REST API

1. Vue d'ensemble

Le Snapshot History est le cœur du système de traçabilité du canevas agricole. À chaque action importante (validation, refoulement), une "photo" complète de toutes les données est sauvegardée. L'historique permet de voir qui a fait quoi et quand, de comparer deux versions, et de visualiser le détail d'une version passée.

📸

Snapshot

Photo immuable de toutes les données d'un canevas à un instant T (engagements, crédits, exploitation…)

📜

Workflow Log

Trace de chaque action métier (qui, quoi, quand, de quelle structure vers quelle structure)

🔀

Comparaison

Affiche les différences entre une version passée et la version courante (montants, statuts, comptes)

⚡

Actions métier

Valider & Transmettre (VALID_DONNEE) ou Refouler (CORRIGE_DONNEE) déclenche un nouveau snapshot

💡
Principe clé : Un snapshot est immuable — une fois créé, il ne change jamais. C'est comme un commit Git : vous ne modifiez pas l'historique, vous ajoutez toujours une nouvelle version. Cela garantit l'intégrité de l'audit.

2. C'est quoi un Snapshot ? (Fonctionnel)

Imaginez un dossier de demande de crédit agricole. Ce dossier passe entre plusieurs services (Agence → Région → Direction). À chaque passage, on fait une photocopie de l'état du dossier à ce moment précis. C'est exactement ce qu'est un snapshot.

Ce qu'un snapshot capture

Donnée capturéePourquoi ?Format stocké
Engagements BNASituation bancaire du client à la BNAJSON (CLOB)
Engagements BCTSituation bancaire nationale (Banque Centrale)JSON (CLOB)
Données des parties liéesActionnaires, responsable, groupe, vendeursJSON (CLOB)
CréditsCourt terme, investissement, achat terrainJSON (CLOB)

🌱
Pour débutant : CLOB = "Character Large Object". C'est comme un champ texte dans la base de données, mais capable de stocker des millions de caractères. Ici, on y stocke du JSON (format texte structuré) représentant des objets complexes.

3. Workflow Métier

Le canevas suit un circuit d'approbation à plusieurs niveaux. Chaque étape crée un snapshot.

1
INIT_DONNEE — Saisie (AGC)

L'agence (AGC) saisit les données du canevas agricole. Pas encore de snapshot.

2
VALID_DONNEE — Validation AGC ➜ DR

L'AGC clique "Valider & Transmettre". Un snapshot V1 est créé et le dossier part à la Direction Régionale (DR). Un log "VALIDER" est enregistré.

3
CORRIGE_DONNEE — Refoulement DR ➜ AGC

La DR constate une erreur et "Refoule" le dossier. Un snapshot V2 est créé avec le motif de refoulement. Le dossier retourne à l'AGC pour correction.

4
PEC_DONNEE → VALIDER_DR → DEC_FINAL…

La DR prend en charge, donne son avis, puis la DC prend la décision finale (accord ou rejet). À chaque étape, un nouveau snapshot est créé.

Statuts possibles d'un snapshot

Statut (code)SignificationQui l'atteint ?

VALID_DONNEEDonnées validées, transmises au DRAGC
CORRIGE_DONNEEDonnées renvoyées pour correctionDR / DC

8. SnapshotService (Appels HTTP)

Le service est la couche de communication entre le composant Angular et le serveur backend. Il utilise HttpClient d'Angular.

@Injectable({ providedIn: 'root' })
export class SnapshotService {

  // URL de base de l'API
  private base = `/api/canevas`

  // ① Récupère la liste de tous les snapshots d'un canevas
  getHistory(id: number): Observable<SnapshotSummary[]> {
    return this.http.get<SnapshotSummary[]>(`${this.base}/${id}/snapshots`)
  }

  // ② Récupère le détail complet d'un snapshot spécifique
  getBySnapshotId(canevasId: number, snapshotId: number) {
    return this.http.get(`${this.base}/${canevasId}/snapshots/${snapshotId}/detail`)
  }

  // ③ Récupère les logs filtrés par rôle
  getWorkflowLog(id: number, typeStructure?: number, codeStructure?: string) {
    let params = new HttpParams()
    if (typeStructure) params = params.set('typeStructure', typeStructure)
    if (codeStructure)  params = params.set('codeStructure', codeStructure)
    return this.http.get(`${this.base}/${id}/snapshots/workflow-log`, { params })
  }

  // ④ Valide et transmet le canevas → crée snapshot VALID_DONNEE
  validerEtTransmettre(id: number, req: ValidationRequest) {
    return this.http.post(`${this.base}/${id}/valider`, req)
  }

  // ⑤ Refoule le canevas → crée snapshot CORRIGE_DONNEE
  refouler(id: number, req: RefoulementRequest) {
    return this.http.post(`${this.base}/${id}/refouler`, req)
  }
}

// Exemple : endpoint validation
@PostMapping("/{id}/valider")
public ResponseEntity<SnapshotResponseDto> valider(
    @PathVariable Long id,
    @RequestBody ValidationRequestDto req
) {
    // 1. Crée le snapshot avec le statut VALID_DONNEE
    CanevasStructureSnapshot snap = snapshotService.createSnapshot(id, req, "VALID_DONNEE")
    // 2. Enregistre le log "VALIDER"
    workflowLogService.log(id, req.fromStructureCode(), req.toStructureCode(),
                           "VALIDER", snap.getVersionNumber(), snap.getSnapshotId(),
                           req.observations(), req.matricule(), null)
    // 3. Renvoie l'ID, la version, et le code structure
    return ResponseEntity.ok(new SnapshotResponseDto(snap.getSnapshotId(),
                                                         snap.getVersionNumber(),
                                                         snap.getStructureCode()))
}

Méthodes de chargement sécurisé (Safe Loading)

🛡️
Ces méthodes (lignes 472-516) utilisent des blocs try-catch pour ne pas faire planter la création du snapshot si une donnée secondaire est introuvable. Si loadEngagementSafe() échoue, le snapshot est quand même créé avec les autres données disponibles.
private EngagementBNADTO loadEngagementSafe(Long numSeqPers) {
    try {
        return engagementService.getByNumSeqPers(numSeqPers)
    } catch (Exception e) {
        log.warn("Engagement not found for {}", numSeqPers)
        return null  // snapshot continue sans cette donnée
    }
}

16. Flux Comparaison de Snapshots

openCompare(oldSnap: SnapshotSummary) {
  this.compareLoading.set(true)

  // Charge les 2 snapshots en parallèle (forkJoin = "attends que les 2 terminent")
  forkJoin({
    old: this.snapshotService.getBySnapshotId(canevasId, oldSnap.snapshotId),
    new: this.snapshotService.getBySnapshotId(canevasId, latestSnapshotId)
  }).subscribe(({ old, new: newSnap }) => {
    this.compareOldSnap.set(old)
    this.compareNewSnap.set(newSnap)
    this.compareMode.set(true)
    this.compareLoading.set(false)
  })

  // diffRows computed() recalcule automatiquement dès que compareOldSnap/compareNewSnap changent
}
🔄
forkJoin est un opérateur RxJS qui attend que toutes les observables se terminent avant d'émettre. C'est l'équivalent de Promise.all() en JavaScript classique.

17. Bugs Potentiels & Points d'Attention

CRITIQUE

Types any dans les interfaces

creditsData: any, exploitationData: any désactivent le typage TypeScript. Si la structure du JSON change côté backend, le frontend plantera silencieusement sans erreur de compilation.

CRITIQUE

Pas de gestion d'erreur HTTP

Les appels .subscribe(data => ...) n'ont pas de handler d'erreur .subscribe({ error: err => ... }). Si l'API échoue, l'utilisateur voit une page vide sans message.

CRITIQUE

Incohérence rôle AGC

canAct = type === 2 || type === 5 exclut le type 1 (AGC). Mais l'AGC doit pouvoir valider. À vérifier et corriger si nécessaire.

MOYEN

N+1 requêtes dans buildGroupeMembers()

Pour chaque membre du groupe, une requête SQL séparée est lancée. Avec 20 membres = 21 requêtes. Il faut utiliser une requête avec JOIN ou un findAllById().

MOYEN

Entité Snapshot legacy non utilisée

L'entité Snapshot.java (ancienne version) coexiste avec CanevasStructureSnapshot.java. Cela crée de la confusion. L'ancienne devrait être supprimée.

MOYEN

Pas de pagination sur l'historique

L'API charge TOUS les snapshots en une fois. Pour un canevas avec 100 versions, cela charge toutes les métadonnées d'un coup. Ajouter Pageable Spring.

18. Améliorations de Performance

PERFORMANCE

Cache côté frontend

Si l'utilisateur ouvre le même snapshot 3 fois, 3 appels HTTP sont faits. Stocker les snapshots déjà chargés dans un Map<id, detail>.

PERFORMANCE

Chargement lazy des CLOB

Pour la liste historique, le backend charge aussi les champs CLOB (gros JSON). Utiliser @Basic(fetch = LAZY) JPA ou une projection sans CLOB pour la liste.

OPTIMISATION

Compression JSON

Les JSON stockés en CLOB peuvent être très volumineux. Activer la compression gzip sur l'API REST (server.compression.enabled=true dans Spring Boot).

OPTIMISATION

Index BDD

Ajouter un index sur (CANEVAS_ID, VERSION_NUMBER) dans CANEVAS_STRUCTURE_SNAPSHOT et (CANEVAS_ID, PERFORMED_AT) dans WORKFLOW_LOG.

Exemple : corriger le problème N+1

// AVANT (mauvais) : 1 requête par membre du groupe
for (AssocieMembre membre : membres) {
    EngagementBNADTO eng = engagementService.getByNumSeqPers(membre.getNumSeqPers())
}

// APRÈS (bon) : 1 seule requête pour tous les membres
List<Long> ids = membres.stream()
    .map(AssocieMembre::getNumSeqPers)
    .collect(Collectors.toList())
Map<Long, EngagementBNADTO> engagementsMap = engagementService.findAllByIds(ids)

19. Améliorations d'Architecture

ARCHITECTURE

Typer les JSON CLOB

Créer des classes Java dédiées (CreditsSnapshot, ExploitationSnapshot) et utiliser le converter JPA @Convert avec ObjectMapper. Plus de Object creditsData non typé.

ARCHITECTURE

Extraire le service workflow

CanevasSnapshotService fait trop de choses (590 lignes). Extraire la construction des données (SnapshotBuilderService) et la logique workflow (WorkflowService).

ARCHITECTURE

Ajouter des tests unitaires

diffRows computed et les méthodes compute*() sont des fonctions pures idéales pour les tests. Ajouter des tests Jasmine/Jest pour chaque indicateur de comparaison.

ARCHITECTURE

Enum pour les statuts

Les statuts ("VALID_DONNEE", "CORRIGE_DONNEE"…) sont des strings partout. Créer un enum SnapshotStatus Java et un type SnapshotStatus TypeScript pour éviter les fautes de frappe.

Exemple : Enum Java pour les statuts

// AVANT (fragile)
snapshotService.createSnapshot(id, req, "VALID_DONNEE") // string libre

// APRÈS (robuste)
public enum SnapshotStatus {
    INIT_DONNEE, VALID_DONNEE, CORRIGE_DONNEE,
    PEC_DONNEE, VALIDER_DR, DEC_FINAL_PRISE_ACCORD, DEC_FINAL_PRISE_REJET
}

snapshotService.createSnapshot(id, req, SnapshotStatus.VALID_DONNEE) // sûr
