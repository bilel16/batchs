Sauvegarder TOUT dans le Snapshot — Guide d'implémentation

Ce guide explique exactement quelles données chaque onglet d'engagement affiche, ce qui est déjà sauvegardé dans le snapshot, ce qui manque, et comment implémenter chaque étape pour qu'un snapshot capture 100% des informations visibles. Tout est détaillé pour un développeur débutant sur ce projet.

5 onglets CanevasSnapshotService.java CanevasStructureSnapshot.java EngagementDetailleDto SnapshotDetailDto snapshot-history.component

1. Objectif — Qu'est-ce qu'on veut faire exactement ?

Le problème aujourd'hui

Quand on sauvegarde un avis, un snapshot est créé. Mais ce snapshot ne capture pas toutes les informations visibles dans les 5 onglets d'engagement. Certaines données (soldes, placements, mouvements, groupes) sont juste relues depuis Oracle à chaque affichage — elles ne sont jamais figées dans l'historique.

Ce qu'on veut

Que le snapshot soit une photo complète et fidèle de ce que l'agent voyait à l'écran au moment de la sauvegarde. Ainsi, en consultant l'historique 6 mois plus tard, on voit exactement les mêmes données.

// ── GROUPE (Onglet 3) — À IMPLÉMENTER ───────────────────────────────────
List<EngagementPartieDto> groupeMembers = new ArrayList<>();

try {
    // Étape 1 : Récupérer le code groupe du client depuis REFCLI
    String codGrpGrp = clientService.getCodGrpByNumSeqPers(numSeqPers.toString());

    if (codGrpGrp != null && !codGrpGrp.isBlank()) {
        // Étape 2 : Récupérer tous les membres du groupe (service déjà existant)
        List<GroupeDTO> membres = clientService.getListeGroupesByNumGRP(codGrpGrp);

        // Étape 3 : Pour chaque membre, charger engagements + placements
        groupeMembers = membres.stream()
            .filter(m -> m.getNumSeqPers() != null)
            .map(m -> {
                String seq        = m.getNumSeqPers();
                EngagementDTO eng = loadEngagementSafe(seq);
                List<ClasseDTO> bna = loadClasseBNASafe(seq);
                List<ClasseDTO> bct = loadClasseBCTSafe(seq);
                List<PlacementDTO> pl = loadPlacementsSafe(seq); // placements du membre

                return EngagementPartieDto.builder()
                    .typePartie("GROUPE")
                    .nom(m.getRelation())
                    .numSeqPers(Long.valueOf(seq))
                    .formeJuridique(m.getFormeJuridique())
                    .activite(m.getActivite())
                    .identifiant(m.getIdentifiant())
                    .engagementsBNA(eng.getListeEngagementBNA())
                    .engagementsBCT(eng.getListeEngagementBCT())
                    .classeBNA(bna)
                    .classeBCT(bct)
                    .placements(pl)
                    .build();
            })
            .collect(Collectors.toList());
    }
} catch (Exception e) {
    log.warn("Groupe non chargé pour numSeqPers={}", numSeqPers);

  identifiant:         string;          // ← NOUVEAU

}

10. Ordre d'implémentation recommandé

Principe

Commencer par les modifications les plus simples (ajouter des champs) avant les plus complexes (implémenter le groupe). Chaque étape est indépendante et testable seule.

1
Migration BDD — Ajouter les 4 colonnes manquantes
À faire en premier

Créer le fichier SQL Flyway V{N}__add_snapshot_tab0_fields.sql :

ALTER TABLE CANEVAS_STRUCTURE_SNAPSHOT ADD (
    SOLDE_ALGEBRIQUE_JSON  CLOB,
    MOUVEMENT_CONFIE_JSON  CLOB,
    PLACEMENTS_JSON        CLOB,
    OBSERVATION_ENG        CLOB
);

⚠️ Chercher le dernier numéro Flyway existant dans db/migration/ et incrémenter de 1.

2
EngagementPartieDto — Ajouter les 7 champs manquants
Simple — 15 min

Ouvrir EngagementPartieDto.java et ajouter :

private String           pieceType;
private String           pieceNumber;
private String           birthOrCreationDate;
private String           activite;
private String           identifiant;
private List<ClasseDTO>  classeBCT;
private List<PlacementDTO> placements;

Ajouter @Getter @Setter ou mettre à jour le @Builder Lombok si utilisé.

3
CanevasStructureSnapshot — Ajouter les 4 champs Java
Simple — 10 min

Ajouter dans CanevasStructureSnapshot.java avec @Lob @Column :

@Lob @Column(name="solde_algebrique_json") private String soldeAlgebriqueJson;
@Lob @Column(name="mouvement_confie_json") private String mouvementConfieJson;
@Lob @Column(name="placements_json")        private String placementsJson;
@Lob @Column(name="observation_eng")        private String observationEng;
4
CanevasSnapshotService — Améliorer associe, responsable, vendeur
30 min

Modifier les 3 méthodes de conversion pour remplir les nouveaux champs :

  • associeToEngagementPartie() : ajouter pieceType, pieceNumber, birthOrCreationDate, classeBCT
  • clientCanvasToPremierResp() : ajouter classeBCT
  • vendeurToEngagementPartie() : ajouter pieceType, pieceNumber, classeBCT
5
CanevasSnapshotService — Charger soldes, mouvements, placements, obsEng
30 min

Dans createSnapshot(), ajouter les 3 méthodes safe et les passer au builder :

List<SommeAlgebriqueDTO> soldes = loadSommeAlgebriquesSafe(seq);
List<MouvementConfieDTO> mouv   = loadMouvementsConfiesSafe(seq);
List<PlacementDTO> placements   = loadPlacementsSafe(seq);
String obsEng = clientCanvasRepository.findByNumSeqpers(...).map(...).orElse("");
6
CanevasSnapshotService — Implémenter le Groupe (Tab 3)
1-2h — le plus complexe

Remplacer groupe(List.of()) par le bloc complet décrit en section 6.2. Vérifier que clientService.getListeGroupesByNumGRP() existe et retourne les bonnes données depuis REFCLI.

⚠️ Attention : si le client n'appartient à aucun groupe, codGrpGrp sera null. Bien gérer ce cas avec un if != null.

7
SnapshotDetailDto — Ajouter les champs dans le DTO de retour
15 min

Le mapper qui convertit CanevasStructureSnapshot → SnapshotDetailDto doit désérialiser les nouveaux champs JSON et les inclure dans la réponse API.

// Dans le mapper SnapshotDetailDto.from(snapshot, objectMapper) :
.soldesAlgebriques(objectMapper.readValue(snapshot.getSoldeAlgebriqueJson(), List.class))
.mouvementsConfie(objectMapper.readValue(snapshot.getMouvementConfieJson(), List.class))
.placements(objectMapper.readValue(snapshot.getPlacementsJson(), List.class))
.observationEng(snapshot.getObservationEng())
8
Frontend — Mettre à jour SnapshotDetailDto.ts + snapshot-history.component.html
1h

Ajouter les nouveaux champs dans l'interface TypeScript (section 9.1) puis ajouter les blocs HTML pour afficher les nouvelles données (section 9.2).

9
Tester — Vérifier en base après une sauvegarde d'avis
Test final
-- Vérifier que les nouvelles colonnes sont remplies
SELECT
    snapshot_id, version_number,
    DBMS_LOB.GETLENGTH(solde_algebrique_json)  AS len_soldes,
    DBMS_LOB.GETLENGTH(mouvement_confie_json)  AS len_mouv,
    DBMS_LOB.GETLENGTH(placements_json)        AS len_placements,
    DBMS_LOB.GETLENGTH(engagement_detaille_json) AS len_detaille
FROM CANEVAS_STRUCTURE_SNAPSHOT
WHERE canevas_id = :votreCanevasId
ORDER BY version_number DESC;

Si len_* > 0 pour les nouvelles colonnes, l'implémentation est correcte.
