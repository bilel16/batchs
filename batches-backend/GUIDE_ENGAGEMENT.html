La section Engagement — Guide complet

Ce guide explique exactement ce qui se passe techniquement et fonctionnellement quand on clique sur « Engagement » dans PGCANVAS. Chaque onglet, chaque champ affiché, chaque appel HTTP, chaque Signal Angular — tout est détaillé pour un développeur débutant.

1. Vue d'ensemble — Qu'est-ce que la section Engagement ?

La section Engagement est une page complète à 5 onglets dans le canvas agricole. Elle affiche les obligations financières (crédits, découverts, escomptes…) d'un client et de toutes les personnes liées à lui.

Pourquoi 5 onglets ?

Un client bancaire peut avoir des engagements à son nom, mais aussi des associés, un gérant (1er responsable), des entreprises partenaires (groupe) et même un vendeur de terrain (dans un crédit achat terrain). Chaque onglet affiche les engagements d'une entité différente liée au même dossier.

2. Architecture technique — Du clic à l'affichage

Voici le chemin complet d'une donnée, depuis le clic de l'utilisateur jusqu'à l'affichage dans le tableau :

1
Utilisateur clique sur un onglet (p-tabView)

PrimeNG déclenche l'event (onChange)="switchHeaders($event)" dans le template HTML.

2
switchHeaders() — Méthode TypeScript

Met à jour le Signal Angular canevasAgrService.activeTabEng.set(indexOnglet).
Pour l'onglet 1 : charge aussi les associés. Pour l'onglet 2 : résout le CIN du responsable.

3
Angular Effect (EngagementService)

L'effect() réagit automatiquement au changement de activeTabEng. Il identifie quel numSeqPers utiliser selon l'onglet actif.

4
HTTP GET vers le backend

Appel GET /api/engagement/all/{numSeqPers} via HttpClient.

5
Spring Boot — EngagementsController

Reçoit la requête et appelle EngagementServiceImpl.getListeEngagementClient().

6
8 requêtes SQL BNA + 1 BCT (Oracle)

JdbcClient exécute les requêtes du fichier engagement-queries.properties sur les schémas SAEB, SAEBAGR, BI_USER, GEN.

7
Cache Caffeine (24h)

Si le même numSeqPers a déjà été chargé aujourd'hui, le résultat vient du cache — aucune requête SQL n'est relancée.

8
JSON → Signal Angular → Template

La réponse JSON met à jour le Signal engagement. Angular détecte le changement et re-rend le tableau automatiquement.

9
Affichage dans le composant app-engagement-bct-bna

Le composant réutilisable reçoit l'objet engagement en @Input Signal et affiche les tableaux BCT + BNA.

Les interfaces de données TypeScript

// _models/Engagement.ts — l'objet racine renvoyé par l'API
interface Engagement {
  numSeqPers:         string;           // Numéro séquentiel du client
  listeEngagementBNA: EngagementBNA[]; // 8 lignes max (une par type de risque)
  listeEngagementBCT: EngagementBct[]; // Historique BCT (par mois/année)
  classeBNA:          Classe[];        // Classification BNA sur 3 ans
  classeBCT:          Classe[];        // Classification BCT sur 3 ans
  erroMessage?:       string;          // Message d'erreur si pas de données
}

// Une ligne de synthèse BNA (ex: "Engagements DP+FC")
interface EngagementBNA {
  typeRisque: string;                 // Nom du type (FCDP, CME, EPS…)
  autorise:   string;                 // Montant total autorisé
  encours:    string;                 // Montant en cours
  impaye:     string;                 // Montant impayé
  utilise:    string;                 // Montant utilisé (surtout AGR)
  engagements: DetailsEngagementBNA[];// Détails (s'ouvrent dans une modal)
}

// Une ligne BCT (Banque Centrale de Tunisie)
interface EngagementBct {
  codFormBct:        string;  // Code forme
  libFormBct:        string;  // Libellé forme (affiché dans la colonne)
  annee:             string;  // Année
  mois:              string;  // Mois
  montantBCT:        string;  // Montant déclaré à la BCT
  montantBNA:        string;  // Montant dans les livres BNA
  pourceBCTBNA:      string;  // % BCT/BNA
  pourceVariationBNA:string;  // % variation BNA
}

Flux technique détaillé à la sélection d'un associé

1

Appel HTTP : GET /api/associe/{numSeqPers} → remplit la liste associes[]

2
Clic sur un associé → onSelectionChange(associe)

3
Résolution du numSeqPers de l'associé

Effect → Chargement engagements associé

L'effet réagit au nouveau signal → GET /api/engagement/all/{associeNumSeqPers}
Le résultat est mis dans engagementAssocie Signal → template se met à jour

// engagements.component.ts — Sélection d'un associé
onSelectionChange(selectedAssocie: Associe) {
  const codTpce = selectedAssocie.pieceType === PieceType.IU ? "14" : "2";

  this.canevasAgrService
    .getClientByContratCpt(codTpce, selectedAssocie.pieceNumber)
    .subscribe(client => {
      this.engagementService
        .setNumSeqPersAssocieEngagement(client.personne?.numSeqPers);
      // → L'effect va lancer GET /api/engagement/all/{numSeqPers}
    });
}

// engagements.component.ts — Signal calculé
readonly filteredVendeurs = computed(() => {
  const credits = this.creditNature1(); // crédits achat terrain
  if (!credits) return [];

  return credits
    .flatMap(c => c.vendeurs ?? [])    // extrait tous les vendeurs
    .filter(v =>                          // garde seulement ceux avec numseqpers
      v.numseqpers !== null &&
      v.numseqpers !== undefined
    );
});

9. Angular Signals & Effets — Le cœur de la réactivité

C'est quoi un Signal ?

Un Signal Angular est une variable réactive. Quand sa valeur change, tout composant ou effect() qui l'utilise se recalcule automatiquement. C'est la façon moderne de gérer l'état dans Angular 17+. Pas besoin de Subject ou d'Observable.

Tous les Signals du service EngagementService

EngagementService — Signals
numSeqPers→ numSeqPers du client en cours de consultation
selectedNumSeqPers→ Signal activé pour l'onglet 0 (Relation)
selectedNumSeqPersAssocie→ Signal activé pour l'onglet 1 (Actionnaire)
selectedNumSeqPersPremResp→ Signal activé pour l'onglet 2 (1er Responsable)
selectedNumSeqPersGroupe→ Signal activé pour l'onglet 3 (Groupe)
selectedNumSeqPersVendeur→ Signal activé pour l'onglet 4 (Vendeur)
engagement→ Données engagement pour l'onglet 0
engagementAssocie→ Données engagement pour l'onglet 1
engagementPreResp→ Données engagement pour l'onglet 2
engagementGroupe→ Données engagement pour l'onglet 3
engagementVendeur→ Données engagement pour l'onglet 4
CanevasAgrService — Signal partagé
activeTabEng= 0, 1, 2, 3 ou 4 → onglet actuellement affiché dans la section Engagement
numSeqPers→ numSeqPers global du client (partagé entre toutes les pages du canvas)

L'Effect central — Le chef d'orchestre

// engagement.service.ts — l'effect réagit à TOUT changement de signal
eff = effect(() => {
  const tab = this.canevasAgrService.activeTabEng(); // lit le signal → crée une dépendance

  switch (tab) {
    case 0:
      const seq0 = this.selectedNumSeqPers(); // lit → dépendance
      if (seq0) {
        this.getEngagementsClientByNumSeqPers(seq0)
          .subscribe(data => this.engagement.set(data)); // met à jour Signal
      }
      break;

    case 1:
      const seq1 = this.selectedNumSeqPersAssocie();
      if (seq1) {
        this.getEngagementsClientByNumSeqPers(seq1)
          .subscribe(data => this.engagementAssocie.set(data));
      }
      break;

    case 2: /* → engagementPreResp */   break;
    case 3: /* → engagementGroupe  */   break;
    case 4: /* → engagementVendeur */   break;
  }
});
Pourquoi ce design est puissant ?

L'effect crée automatiquement des dépendances aux signals qu'il lit. Si activeTabEng change → l'effect se ré-exécute. Si selectedNumSeqPersAssocie change (nouvelle sélection) → l'effect se ré-exécute. Zéro abonnement manuel, zéro gestion de cycle de vie.

public EngagementDTO getListeEngagementClient(String numSeqPers) {

private List<EngagementBNADTO> getListeEngagementsBNAByClient(String numSeqPers) {
    List<EngagementBNADTO> result = new ArrayList<>();

    // 8 appels séquentiels, chacun ajoute une ligne au résultat
    addEngagementFCDP(result, numSeqPers); // SAEB.ENGAG_COTE + CREDIT_CGEPS
    addEngagementCME(result, numSeqPers);  // SAEB.CREDITS_CME
    addEngagementEPS(result, numSeqPers);  // SAEB.CREDIT_CGEPS (EPS)
    addEngagementESC(result, numSeqPers);  // SAEB.CREDIT_ESC
    addEngagementINV(result, numSeqPers);  // SAEB.CREDITS_INV
    addEngagementBPN(result, numSeqPers);  // SAEB.CREDITCCI
    addEngagementAGR(result, numSeqPers);  // SAEBAGR.CREDIT_AGRI
    addEngagementSBE(result, numSeqPers);  // GEN.SBE_TOT_ENCOURS_CDI_PERS

    return result;
}

// Exemple : addEngagementAGR
private void addEngagementAGR(List<EngagementBNADTO> result, String numSeqPers) {
    List<DetailsEngagementBNADTO> details = jdbcClient
        .sql(queryConfig.getQuery("getEngAGR"))   // lu depuis .properties
        .param("numSeqPers", numSeqPers)
        .query(DetailsEngagementBNARowMapper::mapRow)
        .list();

    if (!details.isEmpty()) {
        double autorise = details.stream().mapToDouble(d -> Double.parseDouble(d.getMontantAuto())).sum();
        double encours  = details.stream().mapToDouble(d -> Double.parseDouble(d.getMontAEchPRCred())).sum();
        double impaye   = details.stream().mapToDouble(d -> Double.parseDouble(d.getMontImpPRCred())).sum();

        result.add(new EngagementBNADTO(
            "Engagements AGRICOLE",
            String.valueOf(autorise),
            String.valueOf(encours),
            String.valueOf(impaye),
            "0",
            details
        ));
    }
}

Le fichier engagement-queries.properties

Pourquoi des fichiers .properties pour les SQL ?

Cela permet de modifier les requêtes SQL sans recompiler l'application Java. Les requêtes sont chargées au démarrage par QueryConfig.java et stockées en mémoire. Chaque clé correspond à un nom de requête.

# engagement-queries.properties
# Clé = nom de requête, Valeur = SQL complet

getEngFCDP=SELECT e.NUM_ENG_COTCG AS numId, e.NUM_CCPT_CCPT AS compte, \
    e.MONT_AUT_ECOTCG / 1000 AS montantAuto, ... \
    FROM SAEB.ENGAG_COTE e \
    JOIN SAEB.ENGCOT_PRODUIT ep ON e.NUM_ENG_COTCG = ep.NUM_ENG_COTCG \
    WHERE e.NUM_SEQ_PERS = :numSeqPers \
    AND ep.GP_PRODUIT_CTCG IN ('FC', 'DP')

getEngAGR=SELECT c.NUM_CRED_DETAGR AS numId, c.COD_PRD_PRD AS codPrdPrd, \
    c.MNT_AUTO_CRDAGR / 1000 AS montantAuto, \
    c.ECHOIR_CRED_AGRI / 1000 AS montAEchPRCred, \
    c.IMPAYE_CRED_AGRI / 1000 AS montImpPRCred, ... \
    FROM SAEBAGR.CREDIT_AGRI c \
    WHERE c.NUM_SEQ_PERS = :numSeqPers

getEngBCT=SELECT b.COD_FORM_BCT, b.MONTANT_MILLIME / 1000 AS montantBCT, ... \
    FROM BI_USER.RETOUR_ENGAGEMENT_BCT b \
    WHERE (b.ID_BCT_CLT = :numPcePers OR b.ID_BCT_CLT = :codTpcePers)

Pour un développeur débutant — les 3 points clés à retenir

1. Tout passe par le Signal numSeqPers. Changer ce signal (via sélection d'un onglet, d'un associé, d'un groupe…) déclenche automatiquement l'appel HTTP via l'effect().

2. Le composant app-engagement-bct-bna est réutilisé 5 fois (un par onglet). La seule différence : le Signal engagement qu'il reçoit en @Input.

3. Le backend lance 8 requêtes SQL par appel (une par type BNA) et les agrège en une seule liste. Les résultats sont mis en cache 24h pour éviter de surcharger Oracle.
