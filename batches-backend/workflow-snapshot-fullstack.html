🗺 1. Vue d'ensemble — Comment les deux côtés collaborent

À chaque action workflow (valider, refouler…), le frontend envoie une requête HTTP au backend. Le backend fait 3 choses en une seule transaction : crée un snapshot, enregistre un log, met à jour le canvas. Puis le frontend recharge les données et met à jour l'affichage.

📌 Principe clé Un snapshot = une photographie complète du dossier à un instant T, stockée en JSON en base. Une action = un log dans CANEVAS_WORKFLOW_LOG lié au snapshot créé. Ces deux enregistrements sont créés dans la même transaction Spring avec @Transactional(propagation = REQUIRES_NEW).

@RestController
@RequestMapping("/api/canevas")
public class CanevasSnapshotController {

  // ── POST /api/canevas/{id}/valider ──
  @PostMapping("/{id}/valider")
  public ResponseEntity<SnapshotResponseDto> valider(@PathVariable Long id,
                                             @RequestBody ValidationRequestDto request) {
    // ① Créer le snapshot
    CanevasStructureSnapshot snapshot = snapshotService.createSnapshot(
        id, request.fromStructureCode(), request.fromStructureLabel(),
        request.matricule(), request.matricule(),
        request.observations(), "VALID_DONNEE",  // ← statut fixe
        null);
    // ② Enregistrer le log d'action
    workflowLogService.log(id,
        request.fromStructureCode(), request.toStructureCode(),
        "VALIDER",   // ← action fixe : même endpoint pour Chef Agence ET DR
        snapshot.getVersionNumber(), snapshot.getSnapshotId(),
        request.observations(), request.matricule());
    return ResponseEntity.ok(new SnapshotResponseDto(
        snapshot.getSnapshotId(), snapshot.getVersionNumber(),
        request.fromStructureCode()));
  }

  // ── POST /api/canevas/{id}/refouler ──
  @PostMapping("/{id}/refouler")
  public ResponseEntity<SnapshotResponseDto> refouler(@PathVariable Long id,
                                              @RequestBody RefoulementRequestDto request) {
    CanevasStructureSnapshot snapshot = snapshotService.createSnapshot(
        id, request.fromStructureCode(), request.fromStructureLabel(),
        request.matricule(), request.matricule(),
        request.motif(), "CORRIGE_DONNEE",  // ← statut fixe
        null);
    workflowLogService.log(id, request.fromStructureCode(), request.toStructureCode(),
        "REFOULER", snapshot.getVersionNumber(), snapshot.getSnapshotId(),
        request.motif(), request.matricule());
    return ResponseEntity.ok(new SnapshotResponseDto(
        snapshot.getSnapshotId(), snapshot.getVersionNumber(),
        request.fromStructureCode()));
  }
}
⚙ 4. Backend — La Méthode createSnapshot() en 8 étapes

C'est le cœur du système. Elle est appelée à chaque action workflow (valider ou refouler). Elle collecte toutes les données du dossier depuis plusieurs sources et les sérialise en JSON dans la base.

Calcul de la version suivante

Requête JPA SELECT MAX(version_number) FROM CANEVAS_STRUCTURE_SNAPSHOT WHERE canevas_id = ?. Si aucun snapshot → version = 1. Sinon → MAX + 1.

Chargement du Caneva depuis la base locale

canevaRepository.findById(canevasId). Lance EntityNotFoundException si introuvable. Cet objet contient les crédits, les sites, les actionnaires, etc.

Chargement des engagements depuis Oracle SAEB

engagementService.getListeEngagementClient(numSeqPers) → BNA + BCT. Puis séparément : getHistoriqueClasseBNA(), getHistoriqueClasseBCT(), getHistoriqueRetourClasseBctBNA(). Chaque appel est dans un try/catch — si Oracle SAEB est indisponible, le snapshot est créé avec une liste vide (fail-safe).

Construction du JSON engagement détaillé (5 onglets)

buildFullEngagementDetailleJson(caneva) construit un objet avec 5 clés : relation, actionnaires, premierResponsable, groupe, vendeurs. Pour chaque partie liée, on charge ses propres engagements BNA/BCT et classifications.

Construction des JSON métier

buildCreditsJson() → courtTerme + investissement + achatTerrain · buildExploitationJson() → sites GPS + projetCourtTerme (barème, CA réalisé, CA prévisionnel, 3 mois achat) · buildGarantiesJson() → numCaneva + numSeqPers (partiel)

Sérialisation en JSON avec Jackson ObjectMapper

objectMapper.writeValueAsString(obj) convertit chaque objet Java en chaîne JSON stockée en CLOB. Si erreur → log.error + null stocké (champ nullable).

Persistance du snapshot en base

snapshotRepo.save(snapshot) — INSERT dans CANEVAS_STRUCTURE_SNAPSHOT. Retourne l'entité avec snapshotId généré.

Mise à jour du Canvas parent

caneva.setCurrentVersion(nextVersion), caneva.setCurrentStructure(structureCode), caneva.setLastSnapshotId(saved.getSnapshotId()). Puis canevaRepository.save(caneva). Le canvas sait toujours où il en est.

CanevasSnapshotService.java — createSnapshot() — lignes 51–125
@Transactional(propagation = Propagation.REQUIRES_NEW)
public CanevasStructureSnapshot createSnapshot(
    Long canevasId, String structureCode, String structureLabel,
    String matricule, String createdBy, String observations,
    String statusAtSnapshot, String avisJson) {

  // ÉTAPE 1 — Version suivante (MAX + 1)
  Integer nextVersion = snapshotRepo
      .findMaxVersionByCanevasId(canevasId)  // SELECT MAX(version_number) ...
      .map(v -> v + 1)
      .orElse(1);  // premier snapshot = version 1

  // ÉTAPE 2 — Charger le canevas
  Caneva caneva = canevaRepository.findById(canevasId)
      .orElseThrow(() -> new EntityNotFoundException("Canevas introuvable"));

  // ÉTAPE 3 — Engagements Oracle SAEB (fail-safe : try/catch partout)
  String numSeqPersStr = String.valueOf(caneva.getNumSeqpers());
  EngagementDTO engagement = loadEngagementSafe(numSeqPersStr);  // BNA + BCT
  List<ClasseDTO> classeBNA    = loadClasseBNASafe(numSeqPersStr);   // 3 ans
  List<ClasseDTO> classeBCT    = loadClasseBCTSafe(numSeqPersStr);
  List<ClasseBctDTO> classeRet = loadClasseRetourBCTSafe(numSeqPersStr);

  // ÉTAPE 4 — JSON engagement détaillé (5 onglets)
  String engDetailleJson = buildFullEngagementDetailleJson(caneva);

  // ÉTAPE 5 — JSON données métier
  String creditsJson   = buildCreditsJson(caneva);      // CT, invest, terrain
  String exploitJson   = buildExploitationJson(caneva); // sites + 4 types calcul
  String garantiesJson = buildGarantiesJson(caneva);   // partiel

  // ÉTAPES 6+7 — Construire et persister
  CanevasStructureSnapshot snapshot = CanevasStructureSnapshot.builder()
      .canevasId(canevasId).structureCode(structureCode).versionNumber(nextVersion)
      .statusAtSnapshot(statusAtSnapshot).createdBy(createdBy).matricule(matricule)
      .engagementBnaJson(toJson(engagement.getListeEngagementBNA()))
      .engagementBctJson(toJson(engagement.getListeEngagementBCT()))
      .classeBnaJson(toJson(classeBNA)).classeBctJson(toJson(classeBCT))
      .classeRetourJson(toJson(classeRet))
      .engagementDetailleJson(engDetailleJson)
      .donneesCreditsJson(creditsJson).donneesExploitationJson(exploitJson)
      .donneesGarantiesJson(garantiesJson).donneesAvisJson(avisJson)
      .build();
  CanevasStructureSnapshot saved = snapshotRepo.save(snapshot);  // INSERT SQL

  // ÉTAPE 8 — Mise à jour du Canvas parent
  caneva.setCurrentVersion(nextVersion);
  caneva.setCurrentStructure(structureCode);
  caneva.setLastSnapshotId(saved.getSnapshotId());
  canevaRepository.save(caneva);  // UPDATE SQL

  return saved;
}

public List<CanevasWorkflowLog> getHistoryFiltered(
    Long canevasId, String typeStructure, String codeStructure) {

  if ("1".equals(typeStructure) && codeStructure != null) {
    // Agence : seulement SES propres logs (fromStructure)
    return workflowRepo
      .findByCanevasIdAndFromStructureOrderByPerformedAtDesc(
          canevasId, codeStructure);
  }
  if ("2".equals(typeStructure) && codeStructure != null) {
    // DR : ses logs + logs agences enfants (structureMere)
    List<CanevasWorkflowLog> propres = workflowRepo
      .findByCanevasIdAndFromStructureOrderByPerformedAtDesc(
          canevasId, codeStructure);
    List<CanevasWorkflowLog> agences = workflowRepo
      .findByCanevasIdAndStructureMereOrderByPerformedAtDesc(
          canevasId, codeStructure); // via structureMere
    List<CanevasWorkflowLog> merged = new ArrayList<>(propres);
    merged.addAll(agences);
    merged.sort(Comparator.comparing(CanevasWorkflowLog::getPerformedAt).reversed());
    return merged;
  }
  return workflowRepo.findByCanevasIdOrderByPerformedAtDesc(canevasId); // DC : tout
}

Ce service Angular est la couche d'abstraction entre le composant et l'API REST. Il ne contient aucune logique métier — uniquement des appels HTTP.

snapshot.service.ts — Méthodes HTTP complètes
@Injectable({ providedIn: 'root' })
export class SnapshotService {

  private api = `${environment.apiURL}api/canevas`;  // ex: http://localhost:8080/api/canevas

  // ① POST /valider
  validerEtTransmettre(id: number, req: ValidationRequest): Observable<SnapshotResponse> {
    return this.http.post<SnapshotResponse>(`${this.api}/${id}/valider`, req);
  }

  // ② POST /refouler
  refouler(id: number, req: RefoulementRequest): Observable<SnapshotResponse> {
    return this.http.post<SnapshotResponse>(`${this.api}/${id}/refouler`, req);
  }

  // ③ GET /snapshots — liste avec contrôle d'accès optionnel
  getHistory(id: number, typeStructure?: string, codeStructure?: string)
      : Observable<SnapshotSummary[]> {
    let params = new HttpParams();
    if (typeStructure) params = params.set('typeStructure', typeStructure);
    if (codeStructure) params = params.set('codeStructure', codeStructure);
    return this.http.get<SnapshotSummary[]>(`${this.api}/${id}/snapshots`, { params });
  }

  // ④ GET /snapshots/{snapshotId}/detail
  getBySnapshotId(canevasId: number, snapshotId: number): Observable<SnapshotDetail> {
    return this.http.get<SnapshotDetail>(
      `${this.api}/${canevasId}/snapshots/${snapshotId}/detail`);
  }

  // ⑤ GET /snapshots/workflow-log
  getWorkflowLog(id: number, typeStructure?: string, codeStructure?: string)
      : Observable<WorkflowLogEntry[]> {
    let params = new HttpParams();
    if (typeStructure) params = params.set('typeStructure', typeStructure);
    if (codeStructure) params = params.set('codeStructure', codeStructure);
    return this.http.get<WorkflowLogEntry[]>(
      `${this.api}/${id}/snapshots/workflow-log`, { params });
  }
}

Les 2 Actions principales : valider() et refouler()

snapshot-history.component.ts — lignes 518–556
// ── Bouton "Valider & Transmettre" ──
valider(): void {
  const id = this.activeCanevasId() || this.canevasAgrService.currentIdCaneva();
  if (!id || id <= 0) return;

  this.snapshotService.validerEtTransmettre(id, this.validForm)
    .subscribe({
      next: (res: SnapshotResponse) => {
        this.messageService.add({
          severity: 'success', summary: 'Validé',
          detail: `Snapshot v${res.versionNumber} créé`
        });
        this.showValidDlg.set(false);  // ferme le dialog
        this.loadAll(id);              // rechargement complet
      },
      error: () => this.messageService.add({
        severity: 'error', summary: 'Erreur', detail: 'Échec validation'
      })
    });
}

// ── Bouton "Refouler" ──
refouler(): void {
  let id = this.activeCanevasId() || this.canevasAgrService.currentIdCaneva();
  if (!id || !this.refoulForm.motif?.trim()) {
    this.messageService.add({ severity: 'warn', detail: 'Motif obligatoire' });
    return;
  }
  this.snapshotService.refouler(id, this.refoulForm).subscribe({
    next: (res) => {
      this.showRefoulDlg.set(false);
      this.loadAll(id);  // rechargement complet
    },
    error: () => { /* toast error */ }
  });
}

🚨buildGarantiesJson() ne serialize pas les vraies garantiesDonnées incomplètes

Fichier : CanevasSnapshotService.java, lignes 527–532

La méthode ne stocke que le numCaneva et numSeqPers — pas les vraies données de garanties. C'est pourquoi le frontend affiche les garanties en JSON brut sans structure.

private String buildGarantiesJson(Caneva caneva) {
  Map<String, Object> garanties = new HashMap<>();
  garanties.put("numCaneva",  caneva.getId());       // ← seulement l'ID
  garanties.put("numSeqPers", caneva.getNumSeqpers()); // ← pas les vraies données
  return toJson(garanties);
}

⚠loadAll() appelle getWorkflowLog() SANS paramètres de filtrageLogique

Dans loadAll(), getWorkflowLog(id) est appelé sans typeStructure ni codeStructure — le backend retourne donc tous les logs. Le filtrage se fait uniquement côté client dans le computed filteredLogs. Cela charge des données inutiles sur le réseau et expose les logs d'autres structures au navigateur.

private loadAll(id: number): void {
