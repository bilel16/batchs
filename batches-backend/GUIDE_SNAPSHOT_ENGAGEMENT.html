Sauvegarder l'Avis → charger EngagementDetaillé → créer un Snapshot

Ce guide explique exactement comment, lors de la sauvegarde d'un avis, toutes les données d'engagement (client principal + actionnaires + responsable + groupe + vendeurs) sont chargées dans EngagementDetailleDto et figées dans un snapshot historique. Chaque fichier, chaque ligne de code, chaque champ de BDD — tout est détaillé pour un développeur débutant.

1. Vue d'ensemble — Qu'est-ce qu'on veut faire ?

Le besoin

Quand un agent bancaire clique « Sauvegarder » sur la page Avis, on veut :
① Enregistrer l'avis (opinion favorable/défavorable).
② Prendre une photo (snapshot) de tous les engagements du client + toutes les parties liées (actionnaires, 1er responsable, membres du groupe, vendeurs).
③ Stocker cette photo en base pour qu'on puisse la relire plus tard comme historique.

📋

Avis

Opinion formelle (Favorable / Défavorable) + données crédit + commentaire. Table : AVIS_AGRICOLE

🧩

EngagementDetaillé

Conteneur de tous les engagements des parties liées (actionnaires, responsable, groupe, vendeurs)

📸

Snapshot

Photo complète du dossier à un instant T. Table : CANEVAS_STRUCTURE_SNAPSHOT

🕐

Historique

Chaque sauvegarde d'avis crée une nouvelle version du snapshot (v1, v2, v3…)

3. EngagementDetaillé — Structure et chargement

C'est quoi EngagementDetailleDto ?

C'est un objet Java qui regroupe les engagements de toutes les parties liées au client principal. Il contient 4 listes : actionnaires, 1er responsable, groupe, vendeurs. Chaque partie contient ses propres données BNA + BCT + classifications.

3.1 Structure EngagementDetailleDto

📄 EngagementDetailleDto.java — Conteneur principal
List<EngagementPartieDto> actionnaires // Onglet 1 — associés/actionnaires
EngagementPartieDto premierResponsable // Onglet 2 — gérant/directeur
List<EngagementPartieDto> groupe // Onglet 3 — membres du groupe
List<EngagementPartieDto> vendeurs // Onglet 4 — vendeurs terrain

3.2 Structure EngagementPartieDto (une seule partie)

📄 EngagementPartieDto.java — Données d'une partie liée
String typePartie // "ACTIONNAIRE" | "PREMIER_RESPONSABLE" | "GROUPE" | "VENDEUR"
String nom // Nom + prénom
String cin // Numéro de pièce d'identité
Long numSeqPers // Lien vers REFCLI.PERSONNE
String partCapital // % de participation (pour actionnaires)
String formeJuridique // Forme juridique (pour groupe)
List<EngagementBNADTO> engagementsBNA // 8 types BNA (FCDP, CME, AGR…)
List<EngagementBCTDTO> engagementsBCT // Engagements BCT
List<ClasseDTO> classeBNA // Historique classification BNA (3 ans)
List<ClasseDTO> classeBCT // Historique classification BCT (3 ans)

3.3 Comment EngagementDetaillé est chargé — Logique Java

Fichier : backend-saeb/src/main/java/net/kachout/saeb/service/CanevasSnapshotService.java

// CanevasSnapshotService.java — méthode buildEngagementDetaille() (ligne ~156)
private EngagementDetailleDto buildEngagementDetaille(Caneva caneva) {
    Long numSeqPers = caneva.getNumSeqpers().longValue();

    // ── ACTIONNAIRES (Onglet 1) ────────────────────────
    List<Associe> associes = associeRepository.findAssociesByNumSeqPers(numSeqPers);

    List<EngagementPartieDto> actionnaires = associes.stream()
        .filter(a -> a.getNumSeqPers() != null)  // seulement ceux avec numSeqPers
        .map(a -> {
            EngagementDTO eng = loadEngagementSafe(String.valueOf(a.getNumSeqPers()));
            List<ClasseDTO> classeBNA = loadClasseBNASafe(String.valueOf(a.getNumSeqPers()));
            return EngagementPartieDto.builder()
                .typePartie("ACTIONNAIRE")
                .nom(a.getName())
                .cin(a.getPieceNumber())
                .numSeqPers(a.getNumSeqPers())
                .partCapital(String.valueOf(a.getPartPercentage()))
                .engagementsBNA(eng.getListeEngagementBNA())
                .engagementsBCT(eng.getListeEngagementBCT())
                .classeBNA(classeBNA)
                .build();
        })
        .collect(Collectors.toList());

    // ── 1ER RESPONSABLE (Onglet 2) ────────────────────
    EngagementPartieDto premierResponsable = clientCanvasRepository
        .findByNumSeqpers(numSeqPers)
        .map(cc -> {
            EngagementDTO eng = loadEngagementSafe(String.valueOf(numSeqPers));
            return EngagementPartieDto.builder()
                .typePartie("PREMIER_RESPONSABLE")
                .nom(cc.getNomResponsable() + " " + cc.getPrenomResponsable())
                .cin(cc.getCinResponsable())
                .numSeqPers(numSeqPers)
                .engagementsBNA(eng.getListeEngagementBNA())
                .engagementsBCT(eng.getListeEngagementBCT())
                .build();
        })
        .orElse(null);

    // ── VENDEURS (Onglet 4) ───────────────────────────
    List<EngagementPartieDto> vendeurs = caneva.getCreditAchatTerrains().stream()
        .flatMap(c -> c.getVendeurs().stream())
        .filter(v -> v.getNumseqpers() != null)
        .map(v -> {
            EngagementDTO eng = loadEngagementSafe(String.valueOf(v.getNumseqpers()));
            return EngagementPartieDto.builder()
                .typePartie("VENDEUR")
                .nom(v.getNomPrenom())
                .cin(v.getNumPiece())
                .numSeqPers(v.getNumseqpers().longValue())
                .engagementsBNA(eng.getListeEngagementBNA())
                .engagementsBCT(eng.getListeEngagementBCT())
                .build();
        })
        .collect(Collectors.toList());

    // ── GROUPE (Onglet 3) — ⚠️ PAS ENCORE IMPLÉMENTÉ ─
    return EngagementDetailleDto.builder()
        .actionnaires(actionnaires)
        .premierResponsable(premierResponsable)
        .groupe(List.of())        // ← VIDE — voir section "Ce qui manque"
        .vendeurs(vendeurs)
        .build();
}
⚠️ Point important : le GROUPE n'est pas encore chargé

La méthode buildEngagementDetaille() retourne groupe: List.of() (liste vide). Les membres du groupe ne sont pas encore inclus dans le snapshot. Voir la section 9 — Ce qui manque pour savoir comment l'implémenter.

3.4 Méthodes de chargement des engagements (safe)

// Ces méthodes protègent contre les erreurs (try/catch) lors du chargement
private EngagementDTO loadEngagementSafe(String numSeqPers) {
    try {
        return engagementService.getListeEngagementClient(numSeqPers);
        // Appelle : getListeEngagementsBNAByClient() + getListeEngagementsBCTByClient()
    } catch (Exception e) {
        log.warn("Engagement non trouvé pour numSeqPers={}", numSeqPers);
        return new EngagementDTO(); // objet vide si erreur
    }
}

private List<ClasseDTO> loadClasseBNASafe(String numSeqPers) {
    try {
        return engagementService.getHistoriqueClasseBNA(numSeqPers);
    } catch (Exception e) {
        return List.of();
    }
}

4. Le Snapshot — Structure complète

C'est quoi un snapshot ?

C'est une photo figée du dossier complet à un instant précis. Chaque sauvegarde d'avis crée une nouvelle version numérotée (v1, v2, v3…). Toutes les données sont sérialisées en JSON dans des colonnes CLOB. On peut ainsi relire n'importe quelle version passée du dossier.

4.1 Structure complète de l'entité CanevasStructureSnapshot

📄 CanevasStructureSnapshot.java — Table CANEVAS_STRUCTURE_SNAPSHOT
/* ── Métadonnées ── */
Long snapshotId // PK — auto-généré (IDENTITY)
Long canevasId // FK vers CANEVAS_AGRICOLE
String structureCode // "AGC", "DR", "DC" (Agence / Dir. Régionale / Dir. Centrale)
String structureLabel // Libellé humain (ex: "Agence Tunis Centre")
Integer versionNumber // N° version séquentiel (1, 2, 3…)
String statusAtSnapshot // Stade canvas au moment du snapshot
String createdBy // Nom d'utilisateur
String matricule // Matricule agent
LocalDateTime createdAt // Horodatage (auto SYSTIMESTAMP)
String observations // CLOB — commentaires libres
/* ── Engagements du client principal (Onglet 0) ── */
String engagementBnaJson // CLOB JSON → List<EngagementBNADTO>
String engagementBctJson // CLOB JSON → List<EngagementBCTDTO>
String classeBnaJson // CLOB JSON → List<ClasseDTO> (3 ans)
String classeBctJson // CLOB JSON → List<ClasseDTO> (3 ans)
String classeRetourJson // CLOB JSON → List<ClasseBctDTO>
/* ── EngagementDetaille (Onglets 1-4) ── */
String engagementDetailleJson // CLOB JSON → EngagementDetailleDto { actionnaires, premierResponsable, groupe, vendeurs }
/* ── Données métier ── */
String donneesCreditsJson // CLOB JSON → crédits (CT + INV + Achat Terrain)
String donneesExploitationJson // CLOB JSON → sites d'exploitation
String donneesGarantiesJson // CLOB JSON → garanties
String donneesAvisJson // CLOB JSON → données de l'avis (statusAvis, avisValue, dataCredits…)

4.2 Les deux systèmes de snapshot (Legacy + Nouveau)

📦

Legacy — table SNAPSHOT

Ancien système. Contient juste engagements en JSON. Utilisé comme fallback si un ancien snapshot existe déjà.

📸

Nouveau — CANEVAS_STRUCTURE_SNAPSHOT

Système actuel. Contient toutes les données (engagements + credits + garanties + avis). Version numérotée.

4.3 Logique de fallback (legacy vs nouveau)

// CanevasSnapshotService.java — dans createSnapshot()
String engDetailleJson;

// Essai 1 : Lire depuis l'ancienne table SNAPSHOT (legacy)
engDetailleJson = buildEngagementDetailleFromLegacy(numSeqPers);

if (engDetailleJson == null) {
    // Essai 2 : Construire depuis les données JPA courantes
    engDetailleJson = toJson(buildEngagementDetaille(caneva));
}

① AvisController.java

Point d'entrée HTTP. Orchestre la séquence : avis → snapshot → log.

@PostMapping
public ResponseEntity<AvisDTO> saveAvis(@RequestBody AvisDTO avisDTO) {
    // Étape 1 : Sauvegarder l'avis
    AvisDTO savedAvis = avisService.saveAvis(avisDTO);

    // Étape 2 : Résoudre le statut snapshot
    String statusAtSnapshot = resolveStatusAtSnapshot(
        avisDTO.getStatusAvis(),
        avisDTO.getAvisValue()
    );

    // Étape 3 : Créer le snapshot
    SnapshotResponseDto snap = snapshotService.createSnapshot(
        avisDTO.getNumCaneva(),        // ID du canvas
        avisDTO.getStructure(),         // Code structure émettrice
        avisDTO.getStructureLabel(),    // Libellé structure
        avisDTO.getMatricule(),         // Matricule agent
        getCurrentUsername(),            // Nom utilisateur Spring Security
        avisDTO.getCommentaire(),       // Observations
        statusAtSnapshot,                // Stade résolu
        objectMapper.writeValueAsString(avisDTO) // Avis complet en JSON
    );

    // Étape 4 : Logger le workflow
    workflowLogService.log(avisDTO.getNumCaneva(), statusAtSnapshot, snap.getSnapshotId());

    return ResponseEntity.ok(savedAvis);
}

// Mapping statusAvis → statusAtSnapshot
private String resolveStatusAtSnapshot(String statusAvis, String avisValue) {
    return switch (statusAvis) {
        case "PEC_CCA"        -> "PEC_DONNEE";
        case "PRES_VALIDER"  -> "VALID_DONNEE";
        case "CORRIGER"      -> "CORRIGE_DONNEE";
        case "PEC_AVIS_DEC"  -> "PEC_AVIS_DEC";
        case "VALIDER"       -> "VALIDER_DR";
        case "Envoyer"       -> "EN_COURS_ETUDE";
        case "Décision Finale" ->
            "1".equals(avisValue) ? "DEC_FINAL_PRISE_ACCORD" : "DEC_FINAL_PRISE_REJET";
        default -> statusAvis;
    };
}

@Transactional
public SnapshotResponseDto createSnapshot(
        Long canevasId, String structureCode, String structureLabel,
        String matricule, String createdBy, String observations,
        String statusAtSnapshot, String avisJson) {

    // 1. Numéro de version
    Integer nextVersion = snapshotRepo
        .findMaxVersionByCanevasId(canevasId)
        .map(v -> v + 1)
        .orElse(1);

    // 2. Charger le canvas
    Caneva caneva = canevaRepository.findById(canevasId)
        .orElseThrow(() -> new RuntimeException("Canvas non trouvé"));
    String numSeqPersStr = String.valueOf(caneva.getNumSeqpers());

    // 3. Engagements client principal
    EngagementDTO engagement    = loadEngagementSafe(numSeqPersStr);
    List<ClasseDTO> classeBNA  = loadClasseBNASafe(numSeqPersStr);
    List<ClasseDTO> classeBCT  = loadClasseBCTSafe(numSeqPersStr);
    List<ClasseBctDTO> classeRetour = loadClasseRetourBCTSafe(numSeqPersStr);

    // 4. EngagementDetaillé (actionnaires + responsable + vendeurs + groupe)
    String engDetailleJson = buildEngagementDetailleFromLegacy(caneva.getNumSeqpers().longValue());
    if (engDetailleJson == null) {
        engDetailleJson = toJson(buildEngagementDetaille(caneva));
    }

    // 5. Données métier
    String creditsJson    = buildCreditsJson(caneva);
    String exploitJson    = buildExploitationJson(caneva);
    String garantiesJson  = buildGarantiesJson(caneva);

    // 6. Construction et persistance du snapshot
    CanevasStructureSnapshot snapshot = CanevasStructureSnapshot.builder()
        .canevasId(canevasId)
        .structureCode(structureCode)
        .structureLabel(structureLabel)
        .versionNumber(nextVersion)
        .statusAtSnapshot(statusAtSnapshot)
        .matricule(matricule)
        .createdBy(createdBy)
        .observations(observations)
        .engagementBnaJson(toJson(engagement.getListeEngagementBNA()))
        .engagementBctJson(toJson(engagement.getListeEngagementBCT()))
        .classeBnaJson(toJson(classeBNA))
        .classeBctJson(toJson(classeBCT))
        .classeRetourJson(toJson(classeRetour))
        .engagementDetailleJson(engDetailleJson)
        .donneesCreditsJson(creditsJson)
        .donneesExploitationJson(exploitJson)
        .donneesGarantiesJson(garantiesJson)
        .donneesAvisJson(avisJson)
        .build();

    CanevasStructureSnapshot saved = snapshotRepo.save(snapshot);

    // 7. Mise à jour du canvas
    caneva.setCurrentVersion(nextVersion);
    caneva.setCurrentStructure(structureCode);
    caneva.setLastSnapshotId(saved.getSnapshotId());
    canevaRepository.save(caneva);

    return new SnapshotResponseDto(saved.getSnapshotId(), nextVersion, structureCode);
}

9. Comment implémenter — Étapes concrètes pour un débutant

Voici les étapes dans l'ordre pour comprendre et implémenter le système complet :

1 Vérifier que le backend crée bien le snapshot à chaque sauvegarde d'avis
AvisController.java — @PostMapping

S'assurer que l'appel snapshotService.createSnapshot(...) est bien présent après avisService.saveAvis(avisDTO). Si ce n'est pas le cas, ajouter l'appel. Vérifier aussi que avisJson contient bien le JSON complet de l'avis.

2 Vérifier le chargement des actionnaires dans buildEngagementDetaille()
CanevasSnapshotService.java — buildEngagementDetaille()

S'assurer que associeRepository.findAssociesByNumSeqPers(numSeqPers) retourne bien les associés du canvas. Chaque associé avec un numSeqPers non-null doit avoir ses engagements BNA + BCT chargés via loadEngagementSafe().

// Vérifier que ce code existe et fonctionne
List<Associe> associes = associeRepository.findAssociesByNumSeqPers(numSeqPers);
// Si vide → vérifier que les associés sont bien en base pour ce numSeqPers
3 Vérifier le chargement du 1er Responsable
CanevasSnapshotService.java + ClientCanvasRepository.java

Le responsable est chargé via clientCanvasRepository.findByNumSeqpers(numSeqPers). Il faut que ClientCanvas ait bien les champs nomResponsable, prenomResponsable, cinResponsable remplis pour ce client.

4 Vérifier le chargement des vendeurs
CanevasSnapshotService.java — caneva.getCreditAchatTerrains()

Les vendeurs sont récupérés depuis les crédits achat terrain du canvas. Vérifier que la relation JPA est bien chargée (@OneToMany avec FetchType.EAGER ou dans une @Transactional).

// Vérifier les relations JPA dans Caneva.java
@OneToMany(mappedBy = "caneva", fetch = FetchType.LAZY, cascade = CascadeType.ALL)
private List<CreditAchatTerrain> creditAchatTerrains;

// Et dans CreditAchatTerrain.java :
@OneToMany(mappedBy = "credit", fetch = FetchType.LAZY)
private List<Vendeur> vendeurs;

// ⚠️ Si LAZY, il faut être dans une @Transactional pour charger les vendeurs
5 Tester la création du snapshot

Depuis Postman ou le frontend, sauvegarder un avis et vérifier en base :

-- Vérifier qu'un snapshot a été créé
SELECT snapshot_id, canevas_id, version_number, status_at_snapshot, created_at
FROM CANEVAS_STRUCTURE_SNAPSHOT
WHERE canevas_id = :votreCanevasId
ORDER BY version_number DESC;

-- Vérifier que engagement_detaille_json n'est pas null
SELECT engagement_detaille_json
FROM CANEVAS_STRUCTURE_SNAPSHOT
WHERE snapshot_id = :votreDernierSnapshotId;
6 Vérifier la lecture côté Frontend
snapshot-history.component.ts

Appeler GET /api/snapshots/{canevasId}/history pour voir la liste des versions. Cliquer sur une version pour appeler GET /api/snapshots/{canevasId}/{snapshotId} et vérifier que engagementDetaille dans la réponse contient bien les actionnaires, le responsable, et les vendeurs.

10. Ce qui manque — Gaps à implémenter

⚠️ GAP 1 — Les membres du Groupe ne sont pas chargés dans le snapshot

Problème : Dans buildEngagementDetaille(), la liste groupe est toujours vide :

.groupe(List.of()) // ← NON IMPLÉMENTÉ

Solution : Ajouter le chargement des membres du groupe via REFCLI :

// CanevasSnapshotService.java — dans buildEngagementDetaille()

// ── GROUPE (Onglet 3) — À IMPLÉMENTER ───────────────
List<EngagementPartieDto> groupeMembers = new ArrayList<>();

// Étape 1 : Récupérer le code groupe du client
String codGrpGrp = clientRepository.findCodGrpByNumSeqPers(numSeqPers);

if (codGrpGrp != null) {
    // Étape 2 : Récupérer tous les membres du groupe
    List<GroupeDTO> membres = clientService.getListeGroupesByNumGRP(codGrpGrp);

    // Étape 3 : Pour chaque membre, charger ses engagements
    groupeMembers = membres.stream()
        .filter(m -> m.getNumSeqPers() != null)
        .map(m -> {
            EngagementDTO eng = loadEngagementSafe(m.getNumSeqPers());
            List<ClasseDTO> bna = loadClasseBNASafe(m.getNumSeqPers());
            return EngagementPartieDto.builder()
                .typePartie("GROUPE")
                .nom(m.getRelation())
                .cin(m.getIdentifiant())
                .numSeqPers(Long.valueOf(m.getNumSeqPers()))
                .formeJuridique(m.getFormeJuridique())
                .engagementsBNA(eng.getListeEngagementBNA())
                .engagementsBCT(eng.getListeEngagementBCT())
                .classeBNA(bna)
                .build();
        })
        .collect(Collectors.toList());
}

// Puis dans le return :
return EngagementDetailleDto.builder()
    .actionnaires(actionnaires)
    .premierResponsable(premierResponsable)
    .groupe(groupeMembers)  // ← maintenant rempli
    .vendeurs(vendeurs)
    .build();

Pour retenir les 4 points essentiels :

1. POST /api/avis → déclenche AUTOMATIQUEMENT la création d'un snapshot.
2. Le snapshot charge les engagements en Oracle via loadEngagementSafe() pour chaque entité.
3. Tout est sérialisé en JSON CLOB dans CANEVAS_STRUCTURE_SNAPSHOT.
4. Le groupe (onglet 3) n'est pas encore chargé — c'est le principal gap à implémenter.
