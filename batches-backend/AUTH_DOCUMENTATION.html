1 — C'est quoi l'authentification JWT ?

JWT signifie JSON Web Token. C'est une façon de prouver son identité sans stocker de session côté serveur.

💡 Analogie simple Imaginez un badge d'entrée dans un immeuble. Quand vous vous connectez, le serveur vous donne un badge (le token JWT). À chaque fois que vous essayez d'accéder à une ressource protégée, vous montrez votre badge. Le serveur vérifie le badge mais n'a pas besoin de se souvenir de vous (stateless = sans état).

Structure d'un token JWT

Un token JWT est composé de 3 parties séparées par des points . :

eyJhbGciOiJIUzUxMiJ9   ←  HEADER  (algorithme : HS512)
.
eyJ1c2VybmFtZSI6ImFkbWluIiwicm9sZXMiOlsiUk9MRV9BRE1JTiJdfQ  ←  PAYLOAD (données : username, rôles, expiration)
.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c  ←  SIGNATURE (vérification d'intégrité)
⚠️ Important Le PAYLOAD est encodé en Base64 — il n'est PAS chiffré. N'y mettez jamais de mot de passe. La SIGNATURE, elle, garantit que le token n'a pas été modifié.
PropriétéValeur dans BATCHESExplication
AlgorithmeHS512HMAC avec SHA-512 (clé ≥ 512 bits)
Durée de vie1 heure (3 600 000 ms)Après 1h, le token expire → reconnexion obligatoire
Clé secrèteVariable BATCHES_JWT_SECRETClé Base64 de 64 octets minimum
Contenuusername + rôles (profils) + expirationStocké dans le PAYLOAD du JWT

3 — Backend : Comment ça marche étape par étape

Étape 1 — L'utilisateur envoie ses identifiants

1
POST /authenticate Angular envoie une requête HTTP POST avec {"username": "admin", "password": "admin123"}. Cette URL est publique (pas besoin de token).

Étape 2 — AuthController appelle le serveur externe

Fichier : controllers/AuthController.java

JAVA// Le controller encode les identifiants en Base64
String credentials = username + ":" + password;
String encoded = Base64.getEncoder().encodeToString(credentials.getBytes());

// Il appelle le serveur d'authentification externe (urlAuth)
HttpHeaders headers = new HttpHeaders();
headers.set("Authorization", "Basic " + encoded);  // ← Basic Auth

AuthUser body = new AuthUser(clientIp, codeApp);    // ← IP + code application
AuthResponse response = restTemplate.postForObject(urlAuth, entity, AuthResponse.class);
💡 Pourquoi Base64 ? Le serveur externe attend les identifiants en HTTP Basic Authentication, ce qui utilise le format Base64. Ce n'est pas du chiffrement — c'est un encodage standard.

Étape 6 — Filtre JWT sur chaque requête suivante

Fichier : security/filter/JwtRequestFilter.java

Ce filtre s'exécute automatiquement sur chaque requête HTTP (sauf /authenticate) :

1
Lire le header Authorization — Cherche Bearer eyJhbGci...
2
Extraire le username — Décode le JWT pour lire le subject
3
Appeler urlroles — Récupère les rôles actuels de l'utilisateur depuis le serveur externe
4
Valider le token — Compare les rôles du token avec les rôles frais + vérifie l'expiration
5
Autoriser ou bloquer — Si tout est OK → continue. Sinon → 401 Unauthorized

Gestion des erreurs 401 et 403

CodeFichier responsableQuand ?
401 Unauthorized JwtAuthenticationEntryPoint.java Requête sans token ou token invalide
403 Forbidden JwtAccessDeniedHandler.java Token valide mais rôle insuffisant
Token expiré JwtRequestFilter.java Token valide mais délai de 1h dépassé

Étape 1 — L'utilisateur soumet le formulaire

Fichier : features/login/login.component.ts

TYPESCRIPTonSubmit(): void {
  this.loading = true;

  this.authService.login(username, password).subscribe({

Étape 2 — AuthService envoie la requête et stocke le résultat

TYPESCRIPTlogin(username: string, password: string): Observable<any> {
  return this.http
    .post(environment.apiURL + 'authenticate', { username, password })
    .pipe(
      map(response => {
        this.handleTokenResponse(response); // ← stocke token + user
        return response;
      })
    );
}

private handleTokenResponse(response: any): void {
  // 1. Stocke le token JWT
  this.auth.setToken(response.token);

  // 2. Stocke les infos utilisateur
  const user = {
    username: response.username,
    nom: response.nom,
    prenom: response.prenom,
    email: response.email,
    roles: this.parseRoles(response.roles)
  };
  this.auth.setUser(user);

  // 3. Stocke les menus autorisés
  this.auth.setMenus(this.extractMenus(response.roles));
}

Étape 3 — AuthSignalService persiste l'état dans sessionStorage

TYPESCRIPT// Fichier : auth-signal.service.ts
// Angular Signals = variables réactives (comme useState en React)

readonly user  = signal<User | null>(null);  // ← état de l'utilisateur
readonly token = signal<string | null>(null); // ← le JWT
readonly menus = signal<string[]>([]);         // ← menus autorisés

// Calculé automatiquement depuis user + token
readonly isLoggedIn = computed(() => !!(this.user() && this.token()));

// Chaque modification de signal → sauvegarde automatique dans sessionStorage
effect(() => {
  const state = { user: this.user(), token: this.token(), menus: this.menus() };
  sessionStorage.setItem('__auth_batches', JSON.stringify(state));
});
💡 Pourquoi sessionStorage et non localStorage ? sessionStorage est effacé quand l'onglet du navigateur se ferme. C'est plus sécurisé car si quelqu'un ferme le navigateur, le token ne reste pas.

Étape 4 — L'intercepteur ajoute le token à chaque requête

TYPESCRIPT// Fichier : auth.interceptor.ts
// Ce code s'exécute AUTOMATIQUEMENT avant CHAQUE requête HTTP

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthSignalService).token();

  // Ne pas ajouter le token pour le login
  const skip = req.url.includes('/authenticate');

  if (!skip && token) {
    // Clone la requête et ajoute le header Authorization
    req = req.clone({
      setHeaders: { Authorization: `Bearer ${token}` }
      //  ↑ ce que le backend attend dans le filtre JWT
    });
  }

  return next(req).pipe(
    catchError(err => {
      if (err.status === 401) {
        // Token expiré ou invalide → déconnexion automatique
        auth.clear();
        router.navigate(['/login']);
      }
      return throwError(() => err);
    })
  );
};

Étape 5 — Les Guards protègent les routes

TYPESCRIPT// Fichier : app-routing-module.ts
const routes: Routes = [
  { path: 'login',     canActivate: [loginGuard], ... }, // ← si déjà connecté → /dashboard
  { path: 'dashboard', canActivate: [authGuard],  ... }, // ← si pas connecté  → /login
];

// authGuard : vérifie auth.isLoggedIn()
export const authGuard: CanActivateFn = () => {
  if (auth.isLoggedIn()) return true;
  router.navigate(['/login']);
  return false;
};

Animation de connexion (login → dashboard)

Quand la connexion réussit, une animation s'exécute pendant ~3 secondes avant de naviguer vers le dashboard :

TYPESCRIPTprivate handleLoginSuccess(): void {

  setTimeout(() => {
    this.router.navigate(['dashboard']); // ← navigation après 2980ms
  }, 2980); // ← cette valeur = ANIMATION_DURATION
}

6 — Configuration : les variables d'environnement

⚠️ Ne jamais mettre des mots de passe ou secrets dans le code source ! Toutes les informations sensibles passent par des variables d'environnement (préfixées BATCHES_).
Variable Obligatoire Exemple Description
BATCHES_DB_URL ✅ Oui jdbc:oracle:thin:@10.1.9.10:1521:BNADB URL de la base Oracle
BATCHES_DB_USERNAME ✅ Oui batches_user Utilisateur Oracle
BATCHES_DB_PASSWORD ✅ Oui ******** Mot de passe Oracle
BATCHES_URL_AUTH ✅ Oui http://10.1.9.221:8082/authenticate URL du serveur d'authentification externe
BATCHES_URL_ROLES ✅ Oui http://10.1.9.221:8082/roles URL du serveur de rôles externe
BATCHES_CODE_APP ⬜ Non (défaut: BATCHES) BATCHES Code de l'application dans le serveur auth
BATCHES_JWT_SECRET ⬜ Non (défaut fourni) Clé Base64 de 64 octets min Clé secrète pour signer les JWT (à changer en prod !)
BATCHES_SERVER_PORT ⬜ Non (défaut: 8000) 8000 Port du serveur Spring Boot
BATCHES_ENV ⬜ Non (défaut: dev) dev ou prod En dev → utilise local.ip. En prod → utilise l'IP réelle du client

7 — Scénarios courants : que se passe-t-il quand...

✅ Connexion réussie

1
Angular envoie POST /authenticate → Backend appelle urlAuth → returnCode=0
2
JWT généré → renvoyé à Angular → stocké dans sessionStorage
3
Animation de 3s → navigation vers /dashboard

❌ Mauvais mot de passe

1
Backend appelle urlAuth → returnCode ≠ 0, message = "Mot de passe invalide"
2
AuthController lance une AuthenticationException avec ce message
3
GlobalExceptionHandler retourne {"message": "Mot de passe invalide", "status": "401"}
4
Angular affiche le message sous le champ mot de passe avec animation shake

⏱️ Token expiré (après 1 heure)

1
Angular envoie une requête avec un token expiré
2
JwtRequestFilter détecte ExpiredJwtException → retourne 401 avec message "Token expired"
3
authInterceptor Angular détecte l'erreur 401 → appelle auth.clear() → redirige /login

🔄 Rechargement de page (F5)

1
AuthSignalService s'initialise → lit sessionStorage → recharge user + token + menus
2
isLoggedIn() retourne true → authGuard laisse passer → dashboard affiché

9 — Comment déboguer un problème d'authentification

Problème : "Une erreur est survenue lors de la connexion"

Cause probable : Le serveur d'authentification externe (urlAuth) est inaccessible.
1
Vérifier que BATCHES_URL_AUTH est défini et accessible
2
Regarder les logs Spring Boot : chercher ERROR AuthController
3
Tester manuellement avec Postman : POST sur urlAuth avec Basic Auth

Problème : WeakKeyException (JWT)

Cause : La clé JWT fait moins de 512 bits (64 octets décodés en Base64). 
NODE.JS — Générer une clé validenode -e "const c=require('crypto'); console.log(c.randomBytes(64).toString('base64'));"
# → Copier le résultat dans BATCHES_JWT_SECRET

Problème : 401 sur toutes les requêtes après connexion

1
Ouvrir DevTools (F12) → onglet Network → regarder les headers de la requête
2
Vérifier que le header Authorization: Bearer eyJ... est bien présent
3
Si absent → problème dans auth.interceptor.ts ou token non stocké
4
Si présent mais 401 → vérifier que urlroles répond correctement

Commandes utiles pour vérifier un token JWT

NAVIGATEUR — Console JavaScript// Lire le token stocké
const raw = sessionStorage.getItem('__auth_batches');
const state = JSON.parse(raw);
console.log('Token:', state.token);
console.log('User:', state.user);

// Décoder le payload du JWT (sans vérification de signature)
const payload = JSON.parse(atob(state.token.split('.')[1]));
console.log('Payload:', payload);
console.log('Expire le:', new Date(payload.exp * 1000));
