C'est quoi ce projet ?

Canva Agricole est une application web faite pour la Banque Nationale Agricole (BNA). Les agents de la banque l'utilisent pour gérer les dossiers de crédit agricole : ils créent un "canevas" pour chaque client, saisissent les données du projet (crédits, garanties, élevage, irrigation…), puis analysent si le projet est rentable.

🅰️ Le Frontend (ce que voit l'utilisateur)

Construit avec Angular 17. C'est la partie visuelle : les formulaires, les tableaux, les boutons. Elle tourne dans le navigateur.

📂 frontend-app1/
  • Lance sur : http://localhost:4200
  • Parle au backend via des requêtes HTTP (fetch)
  • Les pages sont des Composants Angular

☕ Le Backend (la logique & les données)

Construit avec Spring Boot 3. C'est le serveur : il reçoit les requêtes, traite les données et parle à la base de données Oracle.

📂 backend-saeb/
  • Lance sur : http://localhost:8081
  • Expose des API REST (GET, POST, PUT, DELETE)
  • Stocke les données dans Oracle Database

Pour chaque fonctionnalité, il y a toujours 7 couches. Comprendre cette chaîne est la clé pour tout modifier ou ajouter.

Exemple concret : Afficher la liste des canevas

Angular Component — Affiche la page

📄 frontend-app1/src/app/_components/pages/canvas.agricole/list/list.component.ts
// Le composant appelle le service dans ngOnInit() ngOnInit() { this.canevasService.getAllCanevas() .subscribe(data => this.canevas = data); }

Angular Service — Fait la requête HTTP

📄 frontend-app1/src/app/_services/canevas.service.ts
getAllCanevas(): Observable<Caneva[]> { // Envoie GET à http://localhost:8081/api/canevas return this.http.get<Caneva[]>(`${this.apiUrl}api/canevas`); }

API HTTP — Le navigateur envoie une requête

GET http://localhost:8081/api/canevas Headers: Authorization: Bearer [token JWT]

Spring Boot Controller — Reçoit la requête

📄 backend-saeb/src/main/java/net/kachout/saeb/web/CanevaController.java
@RestController @RequestMapping("/api/canevas") public class CanevaController { @GetMapping public ResponseEntity<List<CanevaDto>> getAll() { return ResponseEntity.ok(canevaService.findAll()); } }

Spring Boot Service — Traite la logique

📄 backend-saeb/src/main/java/net/kachout/saeb/service/CanevaServiceImpl.java
public List<CanevaDto> findAll() { // Récupère depuis la BDD et convertit en DTO return canevaRepository.findAll() .stream() .map(this::convertToDto) .collect(Collectors.toList()); }

Database Repository — Parle à Oracle

📄 backend-saeb/src/main/java/net/kachout/saeb/repository/CanevaRepository.java
// Spring Data JPA génère automatiquement le SQL public interface CanevaRepository extends JpaRepository<Caneva, Long> { // findAll() est déjà là automatiquement ! List<Caneva> findByNumSeqPers(Long numSeqPers); }

Le Frontend Angular — Comment ça fonctionne

🧩 Anatomie d'un Composant Angular

Chaque page / fonctionnalité est un dossier avec 3 fichiers obligatoires :

📄 fichier.component.ts

La logique TypeScript : données, méthodes, appels aux services.

📄 fichier.component.html

Le template HTML : ce qui s'affiche à l'écran. Formulaires, tableaux, boutons.

📄 fichier.component.css

Les styles CSS spécifiques à ce composant.

📋 Exemple : composant add-canevas

📂 frontend-app1/src/app/_components/pages/canvas.agricole/add-canevas/ ├── add-canevas.component.ts ← logique ├── add-canevas.component.html ← affichage └── add-canevas.component.css ← styles

Le Backend Spring Boot — Comment ça fonctionne

🏗️ Les 4 couches du backend

1. Controller (web/)

Reçoit les requêtes HTTP du frontend. Définit les URLs (/api/canevas, etc.).

@RestController @RequestMapping("/api/canevas") public class CanevaController { @GetMapping ← GET /api/canevas @PostMapping ← POST /api/canevas @PutMapping("/{id}") ← PUT /api/canevas/1 @DeleteMapping ← DELETE }
2. Service (service/)

Contient la logique métier. Calcule, valide, transforme les données.

@Service public class CanevaServiceImpl { // Logique métier ici public CanevaDto save(CanevaDto dto) { // Vérifications, calculs... Caneva entity = convertToEntity(dto); return convertToDto(repo.save(entity)); } }
3. Repository (repository/)

Parle à Oracle. Spring génère le SQL automatiquement à partir des noms de méthodes.

public interface CanevaRepository extends JpaRepository<Caneva, Long> { // Spring génère SELECT * WHERE numSeqPers=? List<Caneva> findByNumSeqPers(Long num); // SELECT * WHERE statut=? List<Caneva> findByStatut(String statut); }
4. Entity (entities/)

Représente une table Oracle en Java. Chaque champ = une colonne.

@Entity @Table(name = "CANEVAS_AGRICOLE") public class Caneva { @Id private Long id; private String titre; private String statut; // 1 champ Java = 1 colonne Oracle }

📦 C'est quoi un DTO ?

Un DTO (Data Transfer Object) est un objet simple qui transporte les données entre le frontend Angular et le backend Spring Boot. C'est la "traduction" entre le monde Angular et le monde Java.

Entity = Table Oracle

// Caneva.java — table en base @Entity class Caneva { Long id; Long numSeqPers; String statut; // Relations complexes... @OneToMany List<Credit> credits; }

DTO = Ce qu'Angular reçoit

// CanevaDto.java — simple à utiliser class CanevaDto { Long id; Long numSeqPers; String statut; // Seulement ce dont Angular a besoin String clientNom; Integer nbCredits; }

Les DTOs sont dans 2 dossiers : dtos/ (anciens) et dtos_/ (récents — utiliser ceux-là en priorité).

💡 Astuces pour déboguer rapidement

🅰️ Angular
  • Ouvre la console navigateur (F12) → tab "Console"
  • Regarde l'onglet "Network" pour voir les requêtes HTTP
  • Utilise console.log(data) dans les services
  • Installe l'extension Chrome "Angular DevTools"
☕ Spring Boot
  • Regarde les logs dans la console IntelliJ/terminal
  • Utilise Swagger : http://localhost:8081/swagger-ui.html
  • Teste l'API avec Postman ou Insomnia
  • Ajouter spring.jpa.show-sql=true pour voir le SQL

  • Si 401 : vérifier que le serveur auth tourne (port 7070)

  • Vérifier le token dans SessionStorage (F12 → Application)
  • En dev : désactiver temporairement la sécurité backend
