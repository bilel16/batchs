1. Vue d'ensemble du projet

PGCANVAS est une application bancaire de financement agricole. Elle permet à des agents bancaires de créer des canvas (dossiers de demande de crédit) pour des clients agriculteurs, de consulter leurs engagements bancaires existants, et d'analyser leurs données financières.

🖥️

Frontend (Angular)

Interface utilisateur dans frontend-app1/ avec composants PrimeNG.

⚙️

Backend (Spring Boot)

API REST dans backend-saeb/. Gère la logique métier et les requêtes SQL.

🗄️

Base de données (Oracle)

Multi-schémas : REFCLI, SAEB, SMILE, BI_USER, CCI, SAEBAGR…

🔒

Sécurité (Keycloak/JWT)

Authentification via Keycloak + tokens JWT pour sécuriser toutes les API.

2. Les Engagements — Définition et fonctionnement

C'est quoi un engagement ? Un engagement est une obligation financière qu'un client a envers la banque. Cela inclut les crédits accordés, les découverts autorisés, les escomptes, etc. Dans PGCANVAS, on distingue deux sources d'engagements : BNA (système interne) et BCT (Banque Centrale de Tunisie, via le système BI).

Les 8 types d'engagements BNA

FCDP

Facilité de Caisse & Découvert Permanent

CME

Crédit de Marché aux Entreprises

EPS

Engagements par signature

ESC

Escompte (effets de commerce)

INV

Crédits d'investissement (CMT)

BPN

Crédits BPN / CCI

AGR

Crédits Agricoles

SBE

Encours CDI (SBE)

Structure d'un objet Engagement (TypeScript)

// frontend-app1/src/app/_models/Engagement.ts
interface Engagement {
  numSeqPers:          string;            // Numéro séquentiel client
  listeEngagementBNA:  EngagementBNA[];  // 8 types d'engagements internes
  listeEngagementBCT:  EngagementBct[];  // Engagements BCT (BCI)
  classeBNA:           Classe[];         // Historique classification BNA (3 ans)
  classeBCT:           Classe[];         // Historique classification BCT (3 ans)
}

// Un seul type d'engagement BNA
interface EngagementBNA {
  typeRisque: string;   // Ex: "FCDP", "CME", "AGR"…
  autorise:   number;   // Montant autorisé
  encours:    number;   // Montant en cours (utilisé)
  impaye:     number;   // Montant impayé
  utilise:    number;   // Montant effectivement utilisé
  engagements: DetailsEngagement[]; // Détails de chaque crédit
}

Comment les engagements sont récupérés — Flux complet

1
Déclencheur Angular (frontend) L'utilisateur clique sur un client. Le EngagementService reçoit le signal numSeqPers via un Angular Signal.
2
Appel HTTP (Angular Service) EngagementService.getEngagementsClientByNumSeqPers(numSeqPers) — envoie un GET à /api/engagement/all/{numSeqPers}
3
Contrôleur REST (Spring Boot) EngagementsController.getEngagementClientByNumSeqPers() reçoit la requête et délègue au service.
4
Service métier (EngagementServiceImpl) Lance 8 requêtes SQL parallèles pour les BNA (FCDP, CME, EPS, ESC, INV, BPN, AGR, SBE) + 1 pour BCT.
5
JdbcClient → Oracle (BDD) Les requêtes SQL sont dans resources/sql/engagements/engagement-queries.properties et sont exécutées sur les schémas SAEB, BI_USER, SAEBAGR, GEN.
6
Cache Caffeine (24h) Le résultat est mis en cache 24h pour éviter des requêtes répétées sur les mêmes données.
7
Retour au frontend L'objet EngagementDTO (BNA + BCT + classifications) est sérialisé en JSON et renvoyé à Angular qui l'affiche.

Exemple de requête SQL (Engagement FCDP)

-- engagement-queries.properties : clé "engagementFCDP"
SELECT
    e.NUM_ENG_COTCG        AS numEng,
    e.MONT_AUT_ECOTCG      AS autorise,
    e.MONT_UTI_ECOTCG      AS utilise,
    e.ECH_FIN_ECOTCG       AS dateEcheance
FROM  SAEB.ENGAG_COTE     e
JOIN  SAEB.ENGCOT_PRODUIT ep ON e.NUM_ENG_COTCG = ep.NUM_ENG_COTCG
WHERE e.NUM_SEQ_PERS   = :numSeqPers      -- paramètre dynamique
  AND ep.GP_PRODUIT_CTCG = 'FC'             -- filtre sur type FC/DP
  AND e.COD_DETAT_ECOTCG = 'V'             -- seulement les actifs

3. Le 1er Responsable

Définition Le 1er responsable est la personne physique principale liée à un compte. Pour une entreprise (personne morale), c'est le gérant, directeur, ou président. Il peut avoir ses propres engagements bancaires que l'on consulte séparément.

Structure de données (DTO Backend)

// ResponsableDTO.java
public class ResponsableDTO {
    private String nomResp;        // Nom
    private String prenomResp;     // Prénom
    private String cinResp;        // Numéro CIN (carte d'identité)
    private String dateNaissResp;  // Date de naissance
    private String contact;        // Téléphone / contact
}

Comment le responsable est récupéré

1
Inclus dans le ClientDTO Quand on charge un client via GET /api/client/getClientByPiece/{typePiece}/{numPiece}, le responsable est déjà inclus dans la réponse.
2
Requête SQL sur SMILE Le backend exécute get1erResponsableByNumSeqPers.sql qui joint les tables SMILE.CONTRAT_CPT, SMILE.MANDAT et SMILE.PERSONNE.
3
Filtre sur le rôle Seules les personnes avec le rôle Gérant, Président, ou Directeur (LIB_QUAL_MP LIKE '%G%', '%PR%', '%DIR%') sont retournées.
4
Engagements du responsable (onglet 2) Quand l'utilisateur clique l'onglet "1er Responsable", Angular récupère le numSeqPers du responsable et charge ses propres engagements via /api/engagement/all/{numSeqPersResponsable}.

SQL de récupération simplifié

-- get1erResponsableByNumSeqPers.sql
SELECT
    p.NOM_NOM_PERS   AS nomResp,
    p.NOM_PRN_PERS   AS prenomResp,
    p.NUM_PCE_PERS   AS cinResp,
    p.NUM_TEL_PERS   AS contact,
    p.DAT_NAIS_PERS  AS dateNaissResp
FROM  SMILE.CONTRAT_CPT     cpt
JOIN  SMILE.MANDAT          m   ON (compte correspondant)
JOIN  SMILE.MANDAT_PERSONNE mp  ON m.NUM_MAND_MAND = mp.NUM_MAND_MAND
JOIN  SMILE.PERSONNE        p   ON mp.NUM_SEQ_PERS = p.NUM_SEQ_PERS
WHERE cpt.num_seq_pers   = :numSeqPers     -- client recherché
  AND cpt.COD_ETAT_CCPT  = 'V'            -- compte actif
  AND m.COD_ETAT_MAND    = 'V'            -- mandat actif
  AND (UPPER(mp.LIB_QUAL_MP) LIKE '%G%'  -- Gérant
    OR UPPER(mp.LIB_QUAL_MP) LIKE '%PR%' -- Président
    OR UPPER(mp.LIB_QUAL_MP) LIKE '%DIR%') -- Directeur
ORDER BY m.NUM_MAND_MAND DESC
FETCH FIRST 1 ROWS ONLY   -- le plus récent seulement

4. Le Groupe

Définition Un groupe est un regroupement d'entreprises ou de personnes physiques liées entre elles (holding, groupe familial, etc.). Un client appartenant à un groupe peut voir les engagements de chaque membre du groupe afin d'avoir une vision consolidée de l'exposition bancaire.

Structure de données

// GroupeDTO.java (Backend) / Groupe.ts (Frontend)
{
  numSeqPers:    "12345",     // Numéro séquentiel du membre
  relation:      "SARL AGRI", // Raison sociale ou nom
  formeJuridique:"SARL",      // Forme juridique
  capital:       "100000",   // Capital social
  activite:      "Élevage",  // Activité principale
  identifiant:   "M123456",  // Matricule fiscal
  dateCreGrp:    "2010-03-15",// Date de création
  gerant:        "Ali Ben Salah" // Nom du gérant
}

Comment les groupes sont récupérés

1
Vérification du code groupe Quand on charge le client, on vérifie si codGrpPers est non-null dans REFCLI.PERSONNE. S'il existe, le client appartient à un groupe.
2
Requête SQL sur REFCLI getListeGroupesByNumGRP.sql récupère tous les membres du groupe via COD_GRP_GRP = :numGrpGrp dans REFCLI.PERSONNE.
3
Onglet 3 — Sélection d'un membre L'utilisateur sélectionne un membre du groupe dans la liste. Angular charge ses engagements individuels via /api/engagement/all/{numSeqPersMembre}.
4
Placements aussi récupérés En plus des engagements, les placements du membre sont chargés via GET /api/client/placements/{numSeqPers}.

SQL de récupération

-- getListeGroupesByNumGRP.sql
SELECT
    p.NUM_SEQ_PERS AS numSeqPers,
    p.DAT_DLV_PERS AS dateCreGrp,
    p.NUM_PCE_PERS AS identifiant,
    CASE WHEN p.NOM_RS_PERS IS NOT NULL
        THEN p.NOM_RS_PERS || ' ' || p.LIB_SIGL_PERS   -- Personne morale
        ELSE p.NOM_NOM_PERS || ' ' || p.NOM_PRN_PERS   -- Personne physique
    END AS relation,
    a.LIB_ACT_ACT  AS activite,
    j.LIB_FJ_FJ    AS formeJuridique
FROM  REFCLI.PERSONNE p
JOIN  REFCLI.CLIENT   c ON p.num_seq_pers = c.num_seq_pers
LEFT JOIN REFCLI.ACTIVITE        a ON p.COD_ACT_ACT = a.COD_ACT_ACT
LEFT JOIN REFCLI.FORME_JURIDIQUE  j ON p.COD_FJ_FJ   = j.COD_FJ_FJ
WHERE COD_GRP_GRP = :numGrpGrp     -- tous les membres de ce groupe

5. Le Vendeur

Définition Un vendeur est le propriétaire actuel d'un terrain / bien immobilier que le client souhaite acheter via un Crédit Achat Terrain (Nature 1). Il est lié à ce crédit et peut lui-même être un client de la banque (via son numseqpers), auquel cas ses engagements peuvent être consultés.

Structure de données

// VendeurDto.java (Backend) / Vendeur interface (Frontend)
{
  id:          "v-001",            // Identifiant interne
  nomPrenom:   "Mohamed Trabelsi",// Nom complet
  typePiece:   "CIN",              // Type de pièce d'identité
  numPiece:    "12345678",         // Numéro de la pièce
  numseqpers:  98765               // Lien vers REFCLI.PERSONNE (optionnel)
}

Table en base de données (créée par migration Flyway V7)

CREATE TABLE VENDEUR (
    id                        VARCHAR2(50)  NOT NULL,
    nomPrenom                 VARCHAR2(255),
    typePiece                 VARCHAR2(20),
    numPiece                  VARCHAR2(20),
    credit_achat_terrain_id   VARCHAR2(50),  -- FK vers CREDIT_ACHAT_TERRAIN
    CONSTRAINT pk_vendeur  PRIMARY KEY (id),
    CONSTRAINT fk_vendeur  FOREIGN KEY (credit_achat_terrain_id)
                           REFERENCES credit_achat_terrain(id)
);

Comment les vendeurs sont récupérés

1
Pas d'endpoint direct pour les vendeurs Les vendeurs font partie du CreditAchatTerrain. Ils sont inclus dans la réponse de GET /api/canevas/{idCaneva}.
2
Filtrage côté Angular (computed signal) Angular filtre tous les vendeurs qui ont un numseqpers non-null, car c'est la condition pour pouvoir charger leurs engagements.
3
Onglet 4 — Sélection vendeur L'utilisateur sélectionne un vendeur. Angular charge ses engagements via /api/engagement/all/{numseqpersVendeur} et aussi les données bilan.

6. Comment les données sont récupérées — Vue globale

6.1 La recherche d'un client (point de départ)

// CanevasAgrService (Angular)
onSearchClient(typePiece: TypePiece, critere: string) {
  this.searchSubject$.next({ typePiece, critere });
}

// Le Subject déclenche automatiquement un appel HTTP :
searchSubject$.pipe(
  switchMap(({ typePiece, critere }) =>
    this.http.get(`/api/client/getClientByPiece/${typePiece}/${critere}`)
  )
).subscribe(client => {
  this.numSeqPers.set(client.personne.numSeqPers); // Signal Angular
});

6.2 Les Angular Signals (réactivité)

C'est quoi un Signal Angular ? C'est une valeur réactive. Quand elle change, tous les composants qui l'utilisent se mettent à jour automatiquement. C'est comme un "abonnement" automatique. 
// EngagementService — tous les états sont des Signals
numSeqPers = signal('');                      // numSeqPers du client principal
selectedNumSeqPersGroupe = signal('');        // membre de groupe sélectionné
selectedNumSeqPersPremResp = signal('');     // responsable sélectionné
selectedNumSeqPersVendeur = signal('');       // vendeur sélectionné

// Effect : dès que numSeqPers change → recharge les engagements
effect(() => {
  const seq = this.numSeqPers();
  if (seq) this.chargerEngagements(seq);
});

6.3 Les deux sources de données Oracle

🏦

Datasource Principale (SAEB)

Contient REFCLI, SAEB, SAEBAGR, SMILE, GEN, CCI. C'est le système bancaire principal BNA.

📊

Datasource Secondaire (BI)

Contient BI_USER. C'est le système Business Intelligence pour les données BCT (reporting external).

8. API REST — Tous les endpoints clés

Engagements

GET /api/engagement/all/{numSeqPers} BNA + BCT + classifications (tout en un)
GET /api/engagement/bna/{numSeqPers} Uniquement les engagements BNA
GET /api/engagement/bct/{numSeqPers} Uniquement les engagements BCT
GET /api/engagement/classeBNA/{numSeqPers} Historique classification BNA (3 ans)
GET /api/engagement/classeBCT/{numSeqPers} Historique classification BCT (3 ans)
GET /api/engagement/effort/{numSeqPers} Montants des termes (calendrier de remboursement)

Client

GET /api/client/getClientByPiece/{codeTypePiece}/{numPiece} Charge client + responsable + groupes + comptes + placements
GET /api/client/{numSeqPers} Détails personne par numSeqPers
GET /api/client/getGroupes/{numGrpGrp} Liste des membres d'un groupe
GET /api/client/placements/{numSeqPers} Placements bancaires du client
GET /api/client/getNameAndNumSeqPers/{typePiece}/{numPiece} Nom + numSeqPers d'une personne (utile pour vendeur)

Canvas & Crédits

GET /api/canevas/{idCaneva} Canvas complet avec tous les crédits (nature 1/2/3) et vendeurs inclus
POST /api/canevas Créer un nouveau canvas agricole
POST /api/credit-achat-terrain Créer un crédit achat terrain (avec vendeurs)
PUT /api/credit-achat-terrain/{id} Modifier un crédit achat terrain
POST /api/client-canvases Sauvegarder les données du client canvas (fiche client)
POST /api/snapshots Sauvegarder un snapshot d'engagement (photo des données à un instant T)

10. Résumé — Le cycle de vie d'une consultation

En 6 étapes simples, voici ce qui se passe quand un agent bancaire ouvre un dossier :
1
Recherche du client L'agent saisit un numéro CIN/Matricule. Angular appelle /api/client/getClientByPiece et charge toutes les infos du client (personne, groupe, responsable, comptes).
2
Chargement des engagements (Onglet 1) Angular appelle /api/engagement/all/{numSeqPers}. Spring Boot lance 9 requêtes SQL (8 BNA + 1 BCT) en parallèle sur Oracle.
3
Engagements du 1er Responsable (Onglet 2) Si l'agent clique l'onglet 2, Angular récupère le numSeqPers du responsable et appelle le même endpoint d'engagements pour lui.
4
Engagements d'un membre du Groupe (Onglet 3) Si le client appartient à un groupe, la liste des membres est affichée. Sélectionner un membre charge ses engagements individuels.
5
Engagements du Vendeur (Onglet 4) Si le canvas contient un crédit achat terrain, les vendeurs identifiés dans la BNA sont listés. Sélectionner un vendeur charge ses engagements.
6
Mise en cache Toutes les données sont mises en cache (Caffeine, 24h). Si l'agent revient sur le même client dans la journée, aucune requête SQL n'est relancée.
