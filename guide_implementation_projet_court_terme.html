1 Comprendre le contexte

Dans ce projet, deux services gèrent les données d'exploitation court terme :

ServiceRôle
FicheEtudeServiceImpl Génère le PDF (Fiche Étude). Contient déjà les 4 rubriques Bareme, CA Réalisé, CA Prévisionnel, 3 Mois Achat pour la génération PDF.
CanevasSnapshotService Crée un "snapshot" (photo instantanée) des données du caneva lors d'un changement de workflow. Stocke ces données en JSON dans la base de données.
Pourquoi faire ça ?
Quand un dossier passe d'un état à un autre (ex: "En cours" → "Validé"), le système prend un snapshot de toutes les données. Actuellement, le snapshot de l'exploitation ne contient que les sites. Il faut y ajouter les 4 types de calcul court terme pour que les données soient complètes dans l'historique.

Pourquoi final ?
Lombok lit tous les champs final non initialisés et génère automatiquement un constructeur qui les reçoit en paramètre. Spring voit ce constructeur et injecte les beans correspondants.
Vérifier les imports : Assurez-vous que les 4 classes sont bien importées en haut du fichier. Si votre IDE (IntelliJ/VS Code) ne les résout pas automatiquement, vérifiez dans FicheEtudeServiceImpl.java lignes 49–58 comment elles sont importées.

4 Étape 2 — Modifier buildExploitationJson()

La méthode reçoit un objet Caneva qui contient numSeqpers et id (= canevaId). On appelle les 4 services avec ces deux clés, exactement comme dans FicheEtudeServiceImpl.

Logique de construction du JSON

Pour chaque type de calcul, on crée une liste de maps. Chaque map représente une ligne du tableau avec ses champs.

Méthode helper : convertir un DTO Bareme en Map

private Map<String, Object> baremeToMap(BaremeCourtTermeDTO b) {
    Map<String, Object> m = new HashMap<>();
    m.put("id",             b.getId());
    m.put("superfecieTete", b.getSuperfecieTete());
    m.put("bareme",         b.getBareme());
    m.put("creditPossible", b.getCreditPossible());
    m.put("sites",          b.getSites());
    boolean retenu = b.getRetenu() != null && b.getRetenu().doubleValue() != -999.0;
    m.put("retenu",         retenu ? b.getRetenu() : null);
    CreditCourtTermeDto c = b.getCreditCourtTerme();
    if (c != null) {
        m.put("produit",           c.getProduit());
        m.put("natureSpeculation", c.getNatureSpeculation());
        m.put("codeSpeculation",   c.getCodeSpeculation());
        m.put("taux",              c.getTaux());
        m.put("marge",             c.getMarge());
        m.put("fond",              c.getFond());
        m.put("montant",           c.getMontant());
    }
    return m;
}
On crée des méthodes helper séparées (une par type de calcul) pour garder le code lisible. Ce pattern est identique à flattenExploitationBaremeCourtTerme() dans FicheEtudeServiceImpl, mais simplifié pour un JSON (sans formatage PDF).

Javaprivate String buildExploitationJson(Caneva caneva) {
    Map<String, Object> exploitation = new HashMap<>();

    // ── Sites (déjà présent) ──────────────────────────────────────────
    exploitation.put("sites", caneva.getSelectedSites() != null
            ? caneva.getSelectedSites().stream()
            .map(s -> {
                Map<String, Object> m = new HashMap<>();
                m.put("id",          s.getId());
                m.put("gouvernorat", s.getGouvernorat());
                m.put("delegation",  s.getDelegation());
                m.put("latitude",    s.getLatitude());
                m.put("longitude",   s.getLongitude());
                return m;
            }).toList()
            : List.of());

    // ── Projet : Court Terme — 4 types de calcul (NOUVEAU) ──────────
    Long numSeqpers = caneva.getNumSeqpers() != null
            ? caneva.getNumSeqpers().longValue() : null;
    Long canevaId   = caneva.getId();

    if (numSeqpers != null && canevaId != null) {
        Map<String, Object> projetCourtTerme = new LinkedHashMap<>();

        // — Type de calcul : Bareme ———————————————————————————————
        try {
            List<BaremeCourtTermeDTO> baremeList =
                    baremeCourtTermeService.findByNumSeqpersAndNumCanva(numSeqpers, canevaId);
            projetCourtTerme.put("bareme", baremeList != null
                    ? baremeList.stream().map(this::snapshotBareme).toList()
                    : List.of());
        } catch (Exception e) {
            log.warn("Snapshot bareme CT échoué canevaId={}", canevaId, e);
            projetCourtTerme.put("bareme", List.of());
        }

        // — Type de calcul : CA réalisé ———————————————————————————
        try {
            List<CACourtTermeDTO> caList =
                    caCourtTermeService.findByNumSeqpersAndNumCanva(numSeqpers, canevaId);
            projetCourtTerme.put("caRealise", caList != null
                    ? caList.stream().map(this::snapshotCaRealise).toList()
                    : List.of());
        } catch (Exception e) {
            log.warn("Snapshot CA réalisé CT échoué canevaId={}", canevaId, e);
            projetCourtTerme.put("caRealise", List.of());
        }

        // — Type de calcul : CA prévisionnel ——————————————————————
        try {
            List<CAPrevCourtTermeDTO> caPrevList =
                    caPrevCourtTermeService.findByNumSeqpersAndNumCanva(numSeqpers, canevaId);
            projetCourtTerme.put("caPrevisionnel", caPrevList != null
                    ? caPrevList.stream().map(this::snapshotCaPrev).toList()
                    : List.of());
        } catch (Exception e) {
            log.warn("Snapshot CA prévi CT échoué canevaId={}", canevaId, e);
            projetCourtTerme.put("caPrevisionnel", List.of());
        }

        // — Type de calcul : 3 mois achat au comptant —————————————
        try {
            List<MoisAchatCourtTermeDTO> maList =
                    moisAchatCourtTermeService.findByNumSeqpersAndNumCanva(numSeqpers, canevaId);
            projetCourtTerme.put("moisAchat", maList != null
                    ? maList.stream().map(this::snapshotMoisAchat).toList()
                    : List.of());
        } catch (Exception e) {
            log.warn("Snapshot moisAchat CT échoué canevaId={}", canevaId, e);
            projetCourtTerme.put("moisAchat", List.of());
        }

        exploitation.put("projetCourtTerme", projetCourtTerme);
    }

    return toJson(exploitation);
}

7 Comment vérifier que ça marche

1. Compilation

mvn compile

Si Spring se plaint d'un bean manquant → vérifier que les interfaces BaremeCourtTermeService, CACourtTermeService, etc. sont bien des @Service ou @Component.

2. Test manuel en base de données

Après avoir déclenché une transition de workflow (ce qui appelle createSnapshot), exécuter cette requête SQL :

SELECT donnees_exploitation_json
FROM canevas_structure_snapshot
WHERE canevas_id = <votre_id>
ORDER BY version_number DESC
LIMIT 1;

Vous devriez voir le JSON avec la clé projetCourtTerme.

3. Points d'attention

Problème possibleSolution
Erreur NullPointerException sur caneva.getNumSeqpers() La guard if (numSeqpers != null && canevaId != null) vous protège déjà.
Les listes sont vides alors qu'il y a des données Vérifier que les services appellent bien la bonne table avec les bons paramètres (numSeqpers + canevaId).
Import CreditCourtTermeDto introuvable Chercher la classe exacte dans net.kachout.saeb.dtos_ (avec underscore).
Spring injection fail : "No qualifying bean of type..." Vérifier que le service cible est annoté @Service et que le package est bien scanné.
