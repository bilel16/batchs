1. Contexte métier — qu'est-ce que la Télé-compensation ?

Chaque jour ouvrable, les banques tunisiennes échangent des instruments de paiement entre elles via un système centralisé géré par la BCT (Banque Centrale de Tunisie). Ce processus s'appelle la Télé-compensation.

Les 3 types d'instruments traités par BatchFrame

InstrumentDéfinition simpleExemple concretCode valeur BCT
Chèque Ordre écrit de payer une somme à quelqu'un à partir d'un compte bancaire Un client BNA reçoit un chèque d'un client STB de 5 000 DT 30, 31, 32, 33
Lettre de Change (Effet) Titre de crédit : le tireur ordonne au tiré de payer à l'échéance Une entreprise reçoit un effet à échéance 30 jours de son fournisseur 40, 41, 42
Prélèvement (Domiciliation) Débit automatique du compte client par une société (eau, électricité, loyer…) STEG prélève automatiquement 120 DT sur le compte d'un client BNA 20

Position (Règlement) Génération et envoi des fichiers de règlement vers la BCT → Débit/crédit des comptes Journée (après validation par la trésorerie)

4. Cycle de vie complet — de main() à la fin du traitement

4.1 Démarrage de l'application

La JVM appelle main()
La méthode public static void main(String[] args) dans BatchFrame est le point d'entrée. Elle utilise EventQueue.invokeLater() pour créer la fenêtre sur le thread Swing (EDT).
Le Look and Feel Metal est appliqué
UIManager.setLookAndFeel("javax.swing.plaf.metal.MetalLookAndFeel") donne à la fenêtre l'apparence standard Java (grise/bleue).
Le constructeur BatchFrame() est exécuté
Création de tous les composants UI (radio buttons, boutons, panneau tableau, label). Le radio "Prélèvement" est présélectionné. L'icône BNA est chargée depuis ./images/BNA.jpg.
La fenêtre s'affiche
frame.setVisible(true) rend la fenêtre visible. L'opérateur voit l'interface et peut interagir.

4.2 L'opérateur clique sur "Lecture Fichier" — Détail complet

// Quand l'opérateur clique "Lecture Fichier" :
actionPerformed(ActionEvent e) {
    // 1. Réinitialiser l'affichage
    getEnd_exec_label().setText("");
    infoVos.clear();
    addOrUpdateEtat(null);       // vide le tableau
    infoEncours.setText("");
    contentPane.updateUI();

    // 2. Vérifier qu'un instrument est sélectionné
    if (!radio_effet.isSelected() && !radio_cheque.isSelected() && !radio_prelev.isSelected()) {
        JOptionPane.showMessageDialog(..., "Veuillez sélectionner avant d'exécuter");
    }

    // 3. Lancer la moulinette dans un THREAD SÉPARÉ
    if (radio_effet.isSelected()) {
        btnExcuter.setEnabled(false);
        btnPosition.setEnabled(false);
        new Thread(new MoulinetteCompensationEffetTest(frame_Instance)).start();

    } else if (radio_prelev.isSelected()) {
        btnExcuter.setEnabled(false);
        new Thread(new MoulinetteInsertionPrelevementsDomiciliationTest(frame_Instance)).start();

    } else if (radio_cheque.isSelected()) {
        btnExcuter.setEnabled(false);
        new Thread(new MoulinetteChequeTest(BatchFrame.INSERT_COMPENSATION, frame_Batch)).start();
    }
}
Pourquoi un Thread séparé ? Le traitement peut durer plusieurs minutes (lecture de milliers de fichiers + insertions base de données). Si on l'exécutait directement sur l'EDT (Event Dispatch Thread de Swing), l'interface serait gelée pendant tout le traitement. En créant un nouveau Thread, l'interface reste réactive et peut mettre à jour le tableau de progression en temps réel.

4.3 Mise à jour de l'interface pendant le traitement

Pendant qu'un thread de moulinette traite les agences, il appelle deux méthodes sur frame_Instance (la référence à BatchFrame) :

Méthode appeléeCe qu'elle fait
frame.updateInfo("Agence 101 EN COURS...") Met à jour le label rouge en haut à droite avec le message de progression.
frame.addOrUpdateEtat(infoVo) Ajoute une nouvelle ligne dans le tableau (si nouvelle agence) ou met à jour la ligne existante (même code structure). Reconstruit et réaffiche tout le tableau.

4.4 Fin du traitement

Succès : mainFrame.getBtnExcuter().setEnabled(true) — bouton réactivé. mainFrame.getEnd_exec_label().setText("Lecture Base Données effet exécutée avec succès")
Erreur : L'exception est catchée, le tableau affiche "ERREUR" pour l'agence concernée. btnPosition.setEnabled(false) reste désactivé pour empêcher la position après une insertion ratée.

5. Moulinettes — détail de chaque traitement

5.1 MoulinetteCompensationEffetTest — Insertion des Effets (Lettres de Change)

Lancée quand : Radio "Lettre de change" + clic "Lecture Fichier".

Chargement du contexte Spring
Lit les 14 fichiers XML de configuration (DAO, services, Quartz, sécurité…) et crée le contexte Spring. C'est cette étape qui initialise la connexion Oracle, les DAOs, les services métier.
Création d'une trace d'exécution
Insère un enregistrement dans la table TRACE_BATCH avec codBatBmet = Constants.COD_BATCH_COMPENSATION_EFFET, l'heure de début, et l'état 1 (en cours).
Initialisation des répertoires
Util.initDirectoriesTeleComp() crée les dossiers de travail (IN, OUT, ARCHIVE…) s'ils n'existent pas.
Lecture des fichiers BCT (GetFilesEffetTrt)
Lit les fichiers de compensation reçus depuis la BCT pour les Effets. Les données brutes sont analysées et préparées pour l'insertion.
Récupération de la liste des agences pilotes
compensationDAO.getListAgencesCompensationPilote() — Interroge Oracle pour obtenir la liste des agences BNA qui sont des agences pilotes de compensation, avec leur date comptable respective.
Boucle agence par agence
Pour chaque agence de type 1 ou 6 (type structure pilote) :
  ① Met à jour l'interface : état "EN COURS INSERT"
  ② Appelle SuivFileTrt.appurementSuiviFileEffet() (nettoyage du suivi fichier)
  ③ Exécute InsertingEffetCmd.execute(compensationVo) (insertion Oracle)
  ④ Met à jour l'interface : état "TERMINÉ"
Mise à jour de la trace et fin
Met à jour la trace avec l'heure de fin. Réactive les boutons. Affiche "Lecture Base Données effet exécutée avec succès" ou le message d'erreur.

5.2 MoulinettePositionEffetTest — Position des Effets

Lancée quand : Radio "Lettre de change" + clic "Position".

Chargement du contexte Spring (identique à l'insertion)
Appel direct de MoulinettePositionCompensationEffet
new MoulinettePositionCompensationEffet(mainFrame).perform()
Cette classe gère la génération des fichiers de position vers la BCT (débit/crédit des comptes).

5.3 MoulinetteInsertionPrelevementsDomiciliationTest — Insertion des Prélèvements

Lancée quand : Radio "Prélèvement" + clic "Lecture Fichier".

Chargement du contexte Spring + initialisation des répertoires
Récupération des journées d'agences
prelevementDAO.getListJourneesAgences() — retourne une liste d'agences avec leur date de journée comptable en cours.
Boucle agence par agence
Pour chaque agence :
  ① Affiche "EN COURS INSERT" dans le tableau
  ② Crée un PrelevementVo avec l'agence et la date
  ③ Instancie MoulinettePrelevementsDomiciliationsACH (nouvelle version ACH depuis 11/03/2026, refonte SNT-ACH)
  ④ Appelle moulinettePrelevements.perform()
  ⑤ Affiche "TERMINÉ" dans le tableau
Fin
frame.getEnd_exec_label().setText("La phase insertion est terminée avec succès")
Réactive le bouton "Lecture Fichier".

5.4 MoulinettePositionPrelevementsDomiciliationTest — Position des Prélèvements

Lancée quand : Radio "Prélèvement" + clic "Position".

Identique à l'insertion jusqu'à la boucle agences
Boucle avec MoulinettePrelevements (ancienne version)
Pour la position, on utilise MoulinettePrelevements (pas la version ACH). Elle lit les prélèvements insérés en base et génère les fichiers de règlement.
Fin
frame.getEnd_exec_label().setText("La phase règlement est terminée avec succès")

6. SwingInfoVo — l'objet de communication

SwingInfoVo est un objet simple (Value Object) qui sert de message entre le thread de traitement et l'interface graphique. Chaque fois qu'une agence change d'état, la moulinette crée un nouveau SwingInfoVo et l'envoie à BatchFrame.addOrUpdateEtat().

Champs les plus importants

ChampTypeValeur exempleUsage
structure String "101" Code de l'agence BNA. Sert de clé pour mettre à jour la bonne ligne du tableau.
etat String "EN COURS INSERT" / "TERMINÉ" / "ERREUR" Affiché dans la colonne "État d'exécution" du tableau.
dateComptable String "27/04/2026" Date de la journée comptable de l'agence.
nombre_total / montant_total String "150" / "45 000" Statistiques utilisées dans la fenêtre Consultation pour les éditions.
nombre_30, montant_30… String "50" / "12 000" Détail par valeur BCT (30=chèque ordinaire, 31=chèque certifié, 40=effet…).

Comment fonctionne addOrUpdateEtat()

public void addOrUpdateEtat(SwingInfoVo vo) {
    // Cherche si l'agence existe déjà dans la liste
    boolean found = false;
    for (int i = 0; i < infoVos.size(); i++) {
        if (vo.getStructure().equals(infoVos.get(i).getStructure())) {
            infoVos.set(i, vo);    // ← MISE À JOUR si trouvée
            found = true;
            break;
        }
    }
    if (!found && vo != null)
        infoVos.add(vo);           // ← AJOUT si nouvelle agence

    // Reconstruit le tableau visuel
    DefaultTableModel model = new DefaultTableModel(etatList, columnNames);
    table = new JTable(model);
    description_panel.removeAll();
    description_panel.add(new JScrollPane(table), BorderLayout.CENTER);
    contentPane.updateUI();        // ← force le rafraîchissement visuel
}
Appel null au démarrage d'un traitement
addOrUpdateEtat(null) est appelé au début de chaque traitement pour vider le tableau. La méthode tolère le null grâce à la condition if (!found && vo != null) qui n'ajoute pas le null. Le tableau est simplement reconstruit vide.

7. Configuration Spring — comment le contexte est chargé

Avant tout traitement métier, chaque moulinette doit charger le contexte Spring pour avoir accès aux DAOs, services et à la connexion Oracle. Voici les fichiers XML chargés :

Fichier XMLContenu
./config/spring.xmlConfiguration principale Spring (datasource Oracle, transaction manager)
./config/applicationContext-DAO.xmlDéfinition de tous les beans DAO (CompensationDAO, PrelevementDAO…)
./config/applicationContext-service.xmlDéfinition des beans de service métier
./config/applicationContext-serviceBatch.xmlServices spécifiques aux batchs (BatchService pour TraceBatch)
./config/applicationContext-traitements.xmlBeans de traitement (Trt, Cmd)
./config/applicationContext-habilitation.xmlGestion des habilitations/profils utilisateurs
./config/applicationContext-resources.xmlRessources partagées (messages, constantes…)
./config/security.xmlConfiguration de la sécurité
./config/quartz-oxia-*.xmlPlanificateur de tâches Quartz (jobs, triggers, calendriers)
./config/applicationContext-1Spring.xmlContexte OXIA Framework (ContextFactory) — initialise le contexte applicatif global
// Chargement en 3 étapes :
String[] path = { "./config/spring.xml", "./config/applicationContext-DAO.xml", ... };

// 1. Crée le contexte Spring standard (tous les beans XML)
ApplicationContext springContext = new FileSystemXmlApplicationContext(path);

// 2. Crée le contexte OXIA et le lie au contexte Spring
Context context = (Context) ContextFactory.initContext("./config/applicationContext-1Spring.xml");
context.setSpringContext(springContext);

// 3. Stocke le contexte OXIA dans un ThreadLocal pour y accéder partout
ContextHandler.setContext(context);

// 4. Récupère un DAO
CompensationDAO compensationDAO = (CompensationDAO) context.getBean("compensationDAO");
Qu'est-ce que OXIA Framework ?
OXIA est le framework interne BNA qui enveloppe Spring. Context est la classe centrale qui donne accès à tous les beans. ContextHandler le stocke dans un ThreadLocal pour qu'il soit accessible depuis n'importe quelle classe sans avoir à le passer en paramètre.
Le contexte Spring est rechargé à chaque clic
Contrairement à une application web qui charge Spring une seule fois au démarrage, chaque moulinette recharge les 14 fichiers XML à chaque exécution. Cela peut prendre quelques secondes. Dans la fenêtre Batch (chèque), le contexte est chargé dans le constructeur (une seule fois), ce qui est plus efficace.

10. Cas réels d'utilisation — scénarios journaliers

Cas 1 — Journée normale Chèque (BatchFrame)

Scénario : Il est 8h00. La BCT a envoyé les fichiers de compensation chèque pendant la nuit. L'opérateur de la trésorerie doit insérer et positionner les chèques de compensation.
Lancer BatchFrame → Sélectionner "Chèque"
Cliquer "Lecture Fichier" → Observer le tableau de progression (agence par agence)
Attendre le message "Lecture Base Données exécutée avec succès"
Cliquer "Consultation" → Vérifier les montants dans l'état récapitulatif
Revenir sur BatchFrame → Cliquer "Position" pour le règlement inter-bancaire
Attendre la confirmation → Le traitement est terminé

Cas 2 — Journée normale Lettre de Change (Effet)

Scénario : Des effets de commerce (lettres de change) arrivés à échéance doivent être traités.
Sélectionner "Lettre de change" dans BatchFrame
Cliquer "Lecture Fichier" → La moulinette lit les fichiers BCT et insère dans Oracle agence par agence
Si une agence est en "ERREUR" → vérifier les logs et rejouer si nécessaire
Après insertion complète → Cliquer "Position" pour générer les fichiers de règlement
Dans Consultation → "Edition globale Effet" pour imprimer le récapitulatif

Cas 3 — Journée normale Prélèvement (Domiciliation)

Scénario : En début de mois, la STEG/SONEDE/opérateurs téléphoniques prélèvent les comptes clients BNA.
Sélectionner "Prélèvement" (sélectionné par défaut) dans BatchFrame
Cliquer "Lecture Fichier" → Insère tous les prélèvements domiciliés dans Oracle via MoulinettePrelevementsDomiciliationsACH
Message : "La phase insertion est terminée avec succès"
Cliquer "Position" → Exécute le débit réel des comptes clients
Message : "La phase règlement est terminée avec succès"

Cas 4 — Traitement Chèque ACH avec la fenêtre Batch

Scénario : Utilisation de la fenêtre Batch (plus complète pour les chèques ACH).
Lancer Batch.main() → La fenêtre charge le contexte Spring immédiatement
Cliquer "1-Insertion" → Lance MoulinetteChequeACH en mode INSERT
Cliquer "Etat Insertion" → Génère et affiche le PDF d'état d'insertion
Si tout est correct → Cliquer "2-Position" pour le règlement
Cliquer "Etat Position" → Génère le PDF de position pour archivage

Cas 5 — Erreur sur une agence spécifique

Scénario : L'agence 205 est en ERREUR dans le tableau, les autres sont TERMINÉ.
Lire le message d'erreur dans infoEncours (label rouge en haut)
Consulter les logs de l'application (Log4j/Apache Commons Logging)
Corriger le problème (fichier manquant, connexion Oracle, données invalides…)
Utiliser le bouton "Forcer Agence" dans Batch pour rejouer uniquement cette agence
Ou utiliser "Valider Insertion" si une insertion partielle doit être forcée

Cas 6 — Consultation historique fin de journée

Scénario : Le chef de service demande un rapport de toutes les opérations de la journée.
Ouvrir la fenêtre Consultation
Saisir la date d'aujourd'hui dans Début et Fin
Sélectionner Produit "Chèque", Sens "Réception"
Cliquer "Edition globale Chèque" → Un rapport PDF JasperReports s'ouvre avec les totaux par type
Répéter pour Effet et Prélèvement si nécessaire

11. Erreurs fréquentes et comment les résoudre

Message d'erreurCause probableSolution
Exception in thread "Thread-1" Erreur dans la moulinette (NullPointerException, SQL…) Consulter les logs. L'agence concernée sera en ERREUR dans le tableau.
Fenêtre gelée sans progression Rare — le thread EDT est bloqué. Normalement impossible avec la conception Thread séparé. Forcer la fermeture et relancer. Vérifier les logs.
Impossible de charger le contexte Spring Fichier XML manquant dans ./config/ ou connexion Oracle impossible Vérifier que tous les fichiers XML existent. Vérifier les credentials Oracle dans spring.xml.
Icône BNA non affichée ./images/BNA.jpg n'existe pas Vérifier que le dossier images/ est à la racine du projet.

Important : position après erreur d'insertion
Quand l'insertion d'une agence échoue pour les Effets, le code fait btnPosition.setEnabled(false) et reste désactivé. Il ne faut jamais effectuer la position si l'insertion est incomplète, car cela engendrerait des opérations déséquilibrées en comptabilité.
